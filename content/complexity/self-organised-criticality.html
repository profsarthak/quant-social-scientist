Self-Organised Criticality

  • Show All Code
  • Hide All Code
  • View Source

Why do power laws appear everywhere? One answer: many systems tune themselves to the knife-edge between order and chaos, with no hand on the dial. There, a single grain of sand can trigger an avalanche of any size.

Drop sand onto a table, one grain at a time. At first the pile just grows. But once its slope reaches the angle of repose, something remarkable happens: the pile stops getting steeper and instead sheds sand in avalanches — most tiny, a few enormous, and every size in between. The pile has tuned itself to a critical state, with no one adjusting anything. Per Bak called this self-organised criticality, and it is the leading candidate for why power laws are so common: a system poised at criticality responds to a small nudge with a cascade whose size is unpredictable and scale-free.

Why it matters

Self-organised criticality (SOC) reframes how we think about big events. In a critical system, the large avalanche is not caused by a large shock — the trigger is the same single grain that usually does nothing. The size of the response is a property of the system’s state, not the size of the cause (Mitchell 2009). That idea reaches directly into the social world: market crashes, mass extinctions, traffic jams, cascading blackouts, and viral fads can all be the rare giant avalanche of a system that spends most of its time quiet. It dissolves the instinct to hunt for a proportionate cause behind every catastrophe — sometimes the cause is ordinary and the system was primed.

The critical state: between order and randomness

Most systems we understand sit at one of two extremes. An ordered system is frozen and predictable — perturb it and the disturbance dies out locally. A disordered (chaotic) system is all noise — perturb it and the effect is random and uncorrelated. The critical state is the razor’s edge between them: the unique point where disturbances are correlated across all scales, so a local nudge can stay local or propagate across the whole system (Mitchell 2009).

Physicists already knew critical points exist — water poised exactly between liquid and gas shows fluctuations at every scale. But that requires fine-tuning the temperature to a precise value. Per Bak’s startling claim was that many systems reach this critical point on their own, as an attractor of their ordinary dynamics — no tuning required. Hence self-organised criticality (Mitchell 2009).

The sandpile model

The canonical model is the abelian sandpile (Bak–Tang–Wiesenfeld). The rules could not be simpler:

  • Each cell of a grid holds some grains of sand.
  • Drop one grain on a random cell.
  • Whenever a cell holds 4 or more grains, it topples: it sheds 4 grains, one to each of its four neighbours. Grains that fall off the edge of the table are lost.
  • Toppling can push a neighbour over 4, so one drop can set off a chain reaction — an avalanche. Count the topplings; that is the avalanche size.

Run it and the pile self-organises: it climbs to the critical slope and stays there, balanced by avalanches. Crucially, the distribution of avalanche sizes is a power law — there is no typical avalanche, just as there is no typical earthquake (Mitchell 2009). The figure builds a real sandpile by hand and measures its avalanches.

import numpy as np
import matplotlib.pyplot as plt
from matplotlib.colors import ListedColormap, LinearSegmentedColormap

rng = np.random.default_rng(0)
N = 50
z = np.zeros((N, N), dtype=np.int64)

def drop(i, j):
    """Add a grain at (i,j) and topple to stability; return avalanche size."""
    z[i, j] += 1
    size = 0
    while True:
        over = z >= 4
        n = int(over.sum())
        if n == 0:
            break
        size += n
        z[over] -= 4
        # each toppling cell sends one grain to each neighbour; edges spill off
        z[1:, :]  += over[:-1, :]    # to the cell below
        z[:-1, :] += over[1:, :]     # to the cell above
        z[:, 1:]  += over[:, :-1]    # to the right
        z[:, :-1] += over[:, 1:]     # to the left
    return size

# warm-up: let the pile self-organise to the critical state (record nothing)
for _ in range(20000):
    drop(rng.integers(N), rng.integers(N))

snapshot = z.copy()

# measure avalanche sizes in the critical state
sizes = np.fromiter(
    (drop(rng.integers(N), rng.integers(N)) for _ in range(40000)),
    dtype=np.int64,
)
sizes = sizes[sizes > 0]

# --- Miller & Page's 1-D forest-fire ridge: 100 sites, lightning f = 0.02 ---
L, f = 100, 0.02

def burn(trees, strike):
    """Every contiguous stand that contains a struck tree burns to the ground."""
    run = np.cumsum(np.r_[1, trees[1:] != trees[:-1]])   # label each run of sites
    hit = np.unique(run[trees & strike])
    return trees & ~np.isin(run, hit)

def production(g, T=3000, burn_in=300):
    """Average trees standing at the end of summer, under one uniform growth rate g."""
    trees, total = np.zeros(L, bool), 0
    for t in range(T):
        trees |= rng.random(L) < g                     # spring: empty sites sprout
        trees = burn(trees, rng.random(L) < f)         # summer: lightning + spread
        total += trees.sum() if t >= burn_in else 0
    return total / (T - burn_in)

gs = np.linspace(0.05, 1.0, 20)
prod = np.array([production(g) for g in gs])
# designed firewalls: stands of k trees (g = 1) split by single empty sites (g = 0);
# a stand survives a summer with probability (1-f)^k
k = 6
firewall = L * k / (k + 1) * (1 - f) ** k

fig, (axL, axM, axR) = plt.subplots(1, 3, figsize=(11.2, 3.9))

im = axL.imshow(snapshot, cmap=ListedColormap(["#f4f3ec", "#dfe2d0", "#f2b48a", "#e8531d"]), vmin=0, vmax=3)
axL.set_title("Sandpile: critical configuration")
axL.set_xticks([]); axL.set_yticks([])
fig.colorbar(im, ax=axL, fraction=0.046, pad=0.04, ticks=[0, 1, 2, 3])

# log-binned avalanche-size distribution
bins = np.logspace(0, np.log10(sizes.max() + 1), 22)
hist, edges = np.histogram(sizes, bins=bins, density=True)
centres = np.sqrt(edges[:-1] * edges[1:])
m = hist > 0
axM.loglog(centres[m], hist[m], "o", color="#161613", ms=5, label="avalanche sizes")
# reference power-law slope for the eye
ref_x = centres[m]
axM.loglog(ref_x, hist[m][0] * (ref_x / ref_x[0]) ** (-1.1),
           "--", color="#5e5e54", lw=1, label="slope ≈ −1.1 (power law)")
axM.set_xlabel("avalanche size  s"); axM.set_ylabel("p(s)")
axM.set_title("Avalanche sizes: scale-free")
axM.legend(fontsize=8, frameon=False)

axR.plot(gs * 100, prod, "o-", color="#161613", ms=4, lw=1.2, label="uniform growth rate (simulated)")
axR.axhline(firewall, color="#e8531d", ls="--", lw=1.4,
            label=f"stands of {k} + firewalls ≈ {firewall:.0f}")
best = prod.argmax()
axR.annotate(f"best uniform ≈ {prod[best]:.0f}", (gs[best] * 100, prod[best]),
             xytext=(8, 30), textcoords="offset points", fontsize=8, color="#5e5e54",
             arrowprops=dict(arrowstyle="-", color="#b7b6a8", lw=0.8))
axR.set_xlabel("growth rate g (%)"); axR.set_ylabel("trees standing (of 100)")
axR.set_title("Forest fire: production vs growth")
axR.set_ylim(0, 90)
axR.legend(fontsize=8, frameon=False, loc="lower center")

fig.tight_layout()
plt.show()

One honest footnote on the name. Miller & Page note that when physicists actually ran the experiment, real sand did not behave as the model predicts, probably because grain shape and water content get in the way. Certain kinds of rice do produce the predicted behaviour (Miller and Page 2007). The sandpile is a thought experiment that some real piles obey, not a law of every pile.

Miller & Page also point out a property that makes the model much easier to work with. Drop two grains in either order and you end with the same final configuration, having lost the same amount of sand off the edge. The model is abelian: order does not matter. So many fiddly modelling choices, such as whether sites update one at a time or all together, turn out to be equivalent, and “many of the agent-interaction details do not matter” (Miller and Page 2007).

A sandpile you can solve with a pencil

Simulation shows that the pile organises itself. Miller & Page also give a version small enough to see why. Line up N sites. Each site holds at most one grain, and a site that receives a second grain topples, sending one grain to each neighbour. Grains pushed past either end are lost (Miller and Page 2007).

Three facts follow, and each one generalises:

  • The pile collapses onto a tiny set of states. Whatever you start with, the pile ends up with at least N-1 sites filled, and it stays that way. From then on it is either completely full or has a single gap somewhere. That is N+1 possible states out of 2^N. With N=30, more than a billion possible configurations shrink to thirty-one. This is self-organisation in its plainest form: the dynamics find a small attractor without anyone steering them (Miller and Page 2007).
  • Avalanche sizes can be counted exactly. Drop a grain into a run of M filled sites, landing d sites in from the nearer end. Two waves of toppling travel outward, reflect off the empty boundaries and cancel when they meet, for a total of d(M-d+1) topples. With N=10 and a full pile, a grain on the edge topples 10 sites and a grain in the middle topples 30. Miller & Page’s exact long-run distribution matches a 100,000-grain simulation to the first decimal (Miller and Page 2007).
  • The tail is fat, but this pile is not a perfect power law. Every avalanche size has the form d(M-d+1), so some sizes can never occur (no prime size above 10, for example). The distribution has heavy tails, but its exact shape is jagged (Miller and Page 2007). A fat tail and a power law are not the same claim. The power-laws entry explains why that distinction matters when you fit data.

The model also explains a pattern people notice in real cascades: a huge avalanche is followed by small ones. The size-30 avalanche happens only when the pile is full and the grain lands in the centre. It leaves the gap in the middle, where the largest avalanche still possible is size 9. Big releases use up the sites that were near the threshold, so the system has to rebuild before it can produce another big one (Miller and Page 2007).

The forest-fire model: criticality as a trade-off

Miller & Page’s second workhorse is a model of trees on a ridge. Each spring, every empty site sprouts a tree with probability g. Each summer, every site is struck by lightning with probability f, and a struck tree burns along with every tree joined to it. Empty sites act as firebreaks. Measure the forest’s production as the trees still standing at the end of summer (Miller and Page 2007).

Two forces pull against each other. Faster growth means more trees. But more trees also form longer joined stands, and one strike can bring down a whole stand. On a ridge of 100 sites with f=0.02, production peaks at a growth rate of about 43% (58.5 trees) and falls off on both sides. At g=1 the ridge is one solid stand, so the first strike clears it (Miller and Page 2007). On a two-dimensional grid, the same trade-off becomes a sharp phase transition. Percolation theory gives a critical growth rate at which scattered clumps of trees suddenly join into one forest-spanning cluster (Miller and Page 2007). This is the same transition as the giant component of a random graph.

Now add selection. Suppose many forests, each with its own fixed g, compete, and the less productive ones are replaced. Because the production curve has a single peak, almost any search method drives the forests to the optimal growth rate. Miller & Page’s point is that this means adaptation leads the system to a precipice. The most productive growth rate sits right at the critical value, where small deviations cost the most yield, so the system ends up “both optimal and fragile” (Miller and Page 2007). In two or more dimensions the effect is stronger (Miller and Page 2007). This gives an economic reason why systems might sit near criticality, alongside the physicist’s self-tuning sandpile. Selection for performance can push a system to the edge.

When the agents can adapt: firewalls and the escape from criticality

Next, Miller & Page let every site set its own growth rate. They start each site at a random rate and adjust it with a simple counterfactual check. If a tree here would have burned, the site lowers its growth rate; otherwise it raises it (Miller and Page 2007). The results surprised them:

  • The average growth rate first falls well below the 43% optimum, then rises and settles near 59%, above it. Production also climbs past the uniform optimum, to over 65% against the earlier best of 58.5% (Miller and Page 2007).
  • The reason is spatial. The ridge sorts itself into stands of high-growth sites separated by sites whose growth rate has fallen to zero. In their sample of eleven sites the rates are 1.00, 1.00, 0.00, 1.00, 1.00, 0.99, 0.00, 0.01, 0.99, 1.00, 1.00. The system has grown firewalls, with no plan and no intention. Miller & Page cite Adam Smith’s invisible hand and call it an example of emergence (Miller and Page 2007).
  • The firewalls are unfair. The sites that end up as firewalls are the most exposed ones, sitting between two fire-prone stands. The adaptive rule drives their growth rate to zero while it rewards their neighbours. They provide the whole ridge’s protection and keep none of the benefit. A far-sighted firewall could set its rate to one and push the job onto a neighbour (Miller and Page 2007).

Smarter agents do not necessarily do better. If agents model their neighbours and each tries hard to grow a tree rather than serve as a firewall, the system can get stuck in “a perpetual muck in which too many trees are chasing too few fire walls.” Miller & Page compare this to simulated annealing: allowing some mistakes, especially cheap ones made early, helps a system escape poor outcomes. “Less perfection is often more” (Miller and Page 2007). With omniscient agents, they conjecture that the most productive layout is a symmetric pattern of six-tree stands separated by single firewalls. The adaptive forest gets only part of the way there: its stands vary from one to six trees, sometimes separated by double firewalls (Miller and Page 2007).

The right panel of Figure 1 runs the fixed-rule ridge again by hand and compares it with a firewall design. Under single firewalls with g=1, a stand of k trees survives a summer with probability (1-f)^k. Our own arithmetic gives about 76 trees per 100 sites for stands of six. Stands of seven are almost exactly tied with six. The figure shows how far a designed layout beats the best uniform growth rate. It does not re-run Miller & Page’s adaptive model, since the text does not give the step size of their adaptation rule.

What makes this matter for social science is Miller & Page’s own conclusion. With adaptive agents, the system “configures itself in a way that mitigates the overall risk by preventing criticality from emerging.” That depends on stable neighbourhoods: firewalls form only because a site keeps the same risky neighbours from one season to the next. If locations were reshuffled every day, the structure would never form. Miller & Page suggest that banks and suburban neighbourhoods, which have stable relationships, can develop firewalls, while the more transient ties of urban neighbourhoods and highway traffic may not (Miller and Page 2007).

The same machinery can be relabelled. Treat trees as risky loans, adjacency as correlated exposure between banks, lightning as defaults and regrowth as new lending, and the forest becomes a model of bank-failure cascades. Miller & Page cite the 1997 Southeast Asian crisis and the Federal Reserve’s 1998 organisation of a $3.5 billion rescue of Long-Term Capital Management (Miller and Page 2007). A model of people who move to the city, join their kin and flee back to the country after anyone they know is mugged turns out to be the same model under different labels (Miller and Page 2007).

Even the sandpile changes when its grains have purposes. Suppose each falling agent can choose where to land and knows what avalanche it will cause. Agents who want small avalanches alternate between sizes 10 and 0, an average of 5. Agents who myopically want the largest avalanche get stuck in a two-cycle of 16 and 12, an average of 14. A cooperative cycle (30, then refill the hole) would average 15. With enough foresight, purposeful agents can produce almost any avalanche distribution they like (Miller and Page 2007).

Is the social world critical? A short checklist

Power laws are real in social data. Miller & Page cite Richardson’s counts of war deaths, 1820–1945: each tenfold drop in deaths roughly triples the number of wars, which fits W \approx 6517\,D^{-1/2} fairly well. City size against rank follows roughly P_i = c/R_i (Miller and Page 2007). Mistaking a fat-tailed process for a Normal one makes you grossly underestimate extremes and dismiss the ones that happen as freak anomalies (Miller and Page 2007). But SOC is only one route to a power law. Simon’s model, in which a city’s chance of attracting the next resident is proportional to its size, also produces one with no criticality at all (Miller and Page 2007). Miller & Page find SOC plausible for forest fires, earthquakes, mudslides and floods, and perhaps for riots, traffic jams and blackouts. City sizes and word frequencies “probably come from very different generative mechanisms” (Miller and Page 2007).

So before claiming a social system is self-organised critical, ask three things. Is there a slow build-up and fast release through local contagion? Is the system fixed-rule, or do its agents adapt to the cascades they experience? And are neighbourhoods stable enough for adaptive firewalls to form?

Tipping points and early warnings

SOC supplies a mechanism for tipping points — the moments when a system flips abruptly from one regime to another (a lake turning turbid, a market crashing, an ice sheet collapsing). As a system drifts toward such a critical transition, it shows a detectable fingerprint called critical slowing down: the stabilising feedbacks that pull it back from disturbances weaken, so it takes longer and longer to recover from small perturbations, and its fluctuations grow more correlated (Mitchell 2009). This slowing recovery — measurable as rising autocorrelation and variance in a time series — has been proposed as a generic early-warning signal of approaching tipping points in ecosystems, climate, and financial markets (Mitchell 2009).

The promise is real but so is the difficulty: the signal is noisy, it can appear without a transition following, and a transition can arrive with little warning. SOC is a powerful lens, not a crystal ball.

Common pitfalls

WarningWhere this goes wrong
  • Demanding a big cause for a big event. In a critical system the trigger of the giant avalanche is the same ordinary grain that usually does nothing — looking for a proportionate cause is a category error. (Mitchell 2009)
  • Assuming criticality must be tuned. The whole point of SOC is that the critical state is an attractor — the system finds it without anyone setting a dial. (Mitchell 2009)
  • Treating early-warning signals as guarantees. Critical slowing down is a statistical tendency, not a deterministic alarm; false positives and silent transitions both occur. (Mitchell 2009)
  • Over-extending the sandpile. SOC is a compelling candidate mechanism for many power laws, not a proof that any particular one is self-organised critical — that still needs the data. (Mitchell 2009) Proportional growth (Simon’s city model) produces power laws with no criticality at all. (Miller and Page 2007)
  • Treating fixed-rule results as if they held for adaptive agents. Sand cannot learn from avalanches; banks, firms and households can. In the forest-fire model, adaptive sites build firewalls that steer the system away from criticality, and purposeful sandpile agents can produce almost any avalanche distribution. Whether a social system is critical depends on whether its agents adapt and whether their neighbourhoods are stable. (Miller and Page 2007)
  • Averaging away the structure. Miller & Page note that standard approximations of the forest-fire model, which work only with the expected rates of growth and fire, describe its statistics poorly. Lightning carves the ridge into coherent clusters of trees and bare ground, and averaging throws that clustering away. (Miller and Page 2007)

Appendix · the mathematics

The abelian sandpile (BTW). On a grid, each site i holds height z_i. The toppling rule is: if z_i \ge z_c (here z_c=4, the number of neighbours), then z_i \to z_i - 4 and each neighbour gains one grain. Grains at the boundary leave the system (open boundary), which is what lets the pile reach a stationary critical state rather than filling up. The model is “abelian” because the final stable configuration is independent of the order in which unstable sites are toppled — a deep property that makes the dynamics well-defined.

Why a power law. At the critical state the system has no characteristic length: the spatial extent of toppling activity is correlated across all scales (a diverging correlation length, exactly as at an equilibrium critical point). The avalanche-size distribution then takes the scale-free form P(s) \sim s^{-\tau} f(s/s_{\max}), a power law with exponent \tau (near 1 for the 2-D BTW pile) cut off only by the finite system size s_{\max}. See power laws & scaling for the statistics of such distributions.

The minimalist sandpile’s avalanche count. Sites hold 0 or 1 grain; a second grain topples a site, sending one grain to each neighbour. Drop a grain into a block of M filled sites bounded by empty sites (or the edges), d sites in from the nearer boundary. Two toppling fronts move one site per step. Over the first d steps 1,2,\dots,d sites topple. For the next M-2d steps, d sites topple per step. The last d steps mirror the first. In total 2\cdot\frac{d(d+1)}{2} + d\,(M-2d) \;=\; d\,(M-d+1), and the expression is symmetric in d \leftrightarrow M-d+1 (Miller and Page 2007). In the long run the pile cycles uniformly through its N+1 states, so the avalanche distribution is a simple count over landing sites and states.

Firewalls, by arithmetic. On a ridge where stands of k trees (g=1) alternate with single empty sites (g=0), each stand burns in a summer with probability 1-(1-f)^k. The expected number of trees standing per site is \pi(k) = \frac{k}{k+1}\,(1-f)^k . With f=0.02: \pi(5)\approx0.753, \pi(6)\approx0.759, \pi(7)\approx0.760, \pi(8)\approx0.756. The curve is very flat near its top. Miller & Page conjecture that stands of six are optimal on their ridge (Miller and Page 2007). In this edge-free calculation, six and seven are effectively tied, and both far exceed the best uniform growth rate (≈ 0.59).

Critical slowing down. Near a critical transition the dominant eigenvalue of the system’s linearised recovery dynamics approaches 1 (discrete time) or 0 (continuous time). The recovery rate \to 0, so the return time after a perturbation diverges; in observable terms the lag-1 autocorrelation \to 1 and the variance rises. These are the statistical early-warning indicators.

::: {.lead-kernel}
Drop sand onto a table, one grain at a time. At first the pile just grows. But once its slope reaches the **angle of repose**, something remarkable happens: the pile stops getting steeper and instead sheds sand in **avalanches** — most tiny, a few enormous, and *every size in between*. The pile has tuned **itself** to a critical state, with no one adjusting anything. Per Bak called this **self-organised criticality**, and it is the leading candidate for *why* power laws are so common: a system poised at criticality responds to a small nudge with a cascade whose size is unpredictable and **scale-free**.
:::

## Why it matters

Self-organised criticality (SOC) reframes how we think about big events. In a critical system, **the large avalanche is not caused by a large shock** — the trigger is the same single grain that usually does nothing. The size of the response is a property of the *system's state*, not the size of the cause [@mitchell_complexity]. That idea reaches directly into the social world: market crashes, mass extinctions, traffic jams, cascading blackouts, and viral fads can all be the rare giant avalanche of a system that spends most of its time quiet. It dissolves the instinct to hunt for a proportionate cause behind every catastrophe — sometimes the cause is ordinary and the system was primed.

## The critical state: between order and randomness

Most systems we understand sit at one of two extremes. An **ordered** system is frozen and predictable — perturb it and the disturbance dies out locally. A **disordered (chaotic)** system is all noise — perturb it and the effect is random and uncorrelated. The **critical state** is the razor's edge *between* them: the unique point where disturbances are correlated across **all scales**, so a local nudge can stay local or propagate across the whole system [@mitchell_complexity].

Physicists already knew critical points exist — water poised exactly between liquid and gas shows fluctuations at every scale. But that requires fine-tuning the temperature to a precise value. Per Bak's startling claim was that many systems reach this critical point **on their own**, as an attractor of their ordinary dynamics — no tuning required. Hence *self-organised* criticality [@mitchell_complexity].

## The sandpile model

The canonical model is the **abelian sandpile** (Bak–Tang–Wiesenfeld). The rules could not be simpler:

- Each cell of a grid holds some grains of sand.
- **Drop** one grain on a random cell.
- Whenever a cell holds **4 or more grains**, it **topples**: it sheds 4 grains, one to each of its four neighbours. Grains that fall off the edge of the table are lost.
- Toppling can push a neighbour over 4, so one drop can set off a **chain reaction** — an avalanche. Count the topplings; that is the avalanche size.

Run it and the pile **self-organises**: it climbs to the critical slope and stays there, balanced by avalanches. Crucially, the distribution of avalanche sizes is a **power law** — there is no typical avalanche, just as there is no typical earthquake [@mitchell_complexity]. The figure builds a real sandpile by hand and measures its avalanches.

```{python}
#| label: fig-sandpile
#| fig-cap: "Criticality built by hand, and a way out of it. LEFT: a snapshot of a 50×50 abelian sandpile after it has self-organised. Each cell holds 0–3 grains (toppling at 4), a critical configuration the dynamics reach and keep without any tuning. MIDDLE: the distribution of avalanche sizes (topplings per dropped grain) on log-log axes, over tens of thousands of drops. It is close to a straight line, a POWER LAW spanning several decades: most drops do nothing, a few set off system-spanning cascades, and every size in between occurs. RIGHT: Miller & Page's forest-fire ridge (100 sites, lightning probability 0.02), re-simulated. Under a single uniform growth rate (dark line), production rises and then collapses as the trees join into one stand that a single strike can clear. The best uniform rate gives about 59 trees, close to the book's 58.5. The orange dashed line is a designed layout (stands of six trees with growth rate 1, split by single empty firewalls). By our own arithmetic it keeps about 76 trees standing. Breaking up the stands beats tuning the growth rate."
#| code-fold: true
#| code-summary: "Show the figure code"

import numpy as np
import matplotlib.pyplot as plt
from matplotlib.colors import ListedColormap, LinearSegmentedColormap

rng = np.random.default_rng(0)
N = 50
z = np.zeros((N, N), dtype=np.int64)

def drop(i, j):
    """Add a grain at (i,j) and topple to stability; return avalanche size."""
    z[i, j] += 1
    size = 0
    while True:
        over = z >= 4
        n = int(over.sum())
        if n == 0:
            break
        size += n
        z[over] -= 4
        # each toppling cell sends one grain to each neighbour; edges spill off
        z[1:, :]  += over[:-1, :]    # to the cell below
        z[:-1, :] += over[1:, :]     # to the cell above
        z[:, 1:]  += over[:, :-1]    # to the right
        z[:, :-1] += over[:, 1:]     # to the left
    return size

# warm-up: let the pile self-organise to the critical state (record nothing)
for _ in range(20000):
    drop(rng.integers(N), rng.integers(N))

snapshot = z.copy()

# measure avalanche sizes in the critical state
sizes = np.fromiter(
    (drop(rng.integers(N), rng.integers(N)) for _ in range(40000)),
    dtype=np.int64,
)
sizes = sizes[sizes > 0]

# --- Miller & Page's 1-D forest-fire ridge: 100 sites, lightning f = 0.02 ---
L, f = 100, 0.02

def burn(trees, strike):
    """Every contiguous stand that contains a struck tree burns to the ground."""
    run = np.cumsum(np.r_[1, trees[1:] != trees[:-1]])   # label each run of sites
    hit = np.unique(run[trees & strike])
    return trees & ~np.isin(run, hit)

def production(g, T=3000, burn_in=300):
    """Average trees standing at the end of summer, under one uniform growth rate g."""
    trees, total = np.zeros(L, bool), 0
    for t in range(T):
        trees |= rng.random(L) < g                     # spring: empty sites sprout
        trees = burn(trees, rng.random(L) < f)         # summer: lightning + spread
        total += trees.sum() if t >= burn_in else 0
    return total / (T - burn_in)

gs = np.linspace(0.05, 1.0, 20)
prod = np.array([production(g) for g in gs])
# designed firewalls: stands of k trees (g = 1) split by single empty sites (g = 0);
# a stand survives a summer with probability (1-f)^k
k = 6
firewall = L * k / (k + 1) * (1 - f) ** k

fig, (axL, axM, axR) = plt.subplots(1, 3, figsize=(11.2, 3.9))

im = axL.imshow(snapshot, cmap=ListedColormap(["#f4f3ec", "#dfe2d0", "#f2b48a", "#e8531d"]), vmin=0, vmax=3)
axL.set_title("Sandpile: critical configuration")
axL.set_xticks([]); axL.set_yticks([])
fig.colorbar(im, ax=axL, fraction=0.046, pad=0.04, ticks=[0, 1, 2, 3])

# log-binned avalanche-size distribution
bins = np.logspace(0, np.log10(sizes.max() + 1), 22)
hist, edges = np.histogram(sizes, bins=bins, density=True)
centres = np.sqrt(edges[:-1] * edges[1:])
m = hist > 0
axM.loglog(centres[m], hist[m], "o", color="#161613", ms=5, label="avalanche sizes")
# reference power-law slope for the eye
ref_x = centres[m]
axM.loglog(ref_x, hist[m][0] * (ref_x / ref_x[0]) ** (-1.1),
           "--", color="#5e5e54", lw=1, label="slope ≈ −1.1 (power law)")
axM.set_xlabel("avalanche size  s"); axM.set_ylabel("p(s)")
axM.set_title("Avalanche sizes: scale-free")
axM.legend(fontsize=8, frameon=False)

axR.plot(gs * 100, prod, "o-", color="#161613", ms=4, lw=1.2, label="uniform growth rate (simulated)")
axR.axhline(firewall, color="#e8531d", ls="--", lw=1.4,
            label=f"stands of {k} + firewalls ≈ {firewall:.0f}")
best = prod.argmax()
axR.annotate(f"best uniform ≈ {prod[best]:.0f}", (gs[best] * 100, prod[best]),
             xytext=(8, 30), textcoords="offset points", fontsize=8, color="#5e5e54",
             arrowprops=dict(arrowstyle="-", color="#b7b6a8", lw=0.8))
axR.set_xlabel("growth rate g (%)"); axR.set_ylabel("trees standing (of 100)")
axR.set_title("Forest fire: production vs growth")
axR.set_ylim(0, 90)
axR.legend(fontsize=8, frameon=False, loc="lower center")

fig.tight_layout()
plt.show()
```

One honest footnote on the name. Miller & Page note that when physicists actually ran the experiment, **real sand did not behave as the model predicts**, probably because grain shape and water content get in the way. Certain kinds of **rice** do produce the predicted behaviour [@millerpage_cas]. The sandpile is a thought experiment that some real piles obey, not a law of every pile.

Miller & Page also point out a property that makes the model much easier to work with. Drop two grains in either order and you end with the **same final configuration**, having lost the same amount of sand off the edge. The model is *abelian*: order does not matter. So many fiddly modelling choices, such as whether sites update one at a time or all together, turn out to be equivalent, and "many of the agent-interaction details do not matter" [@millerpage_cas].

## A sandpile you can solve with a pencil

Simulation shows *that* the pile organises itself. Miller & Page also give a version small enough to see *why*. Line up $N$ sites. Each site holds at most one grain, and a site that receives a second grain topples, sending one grain to each neighbour. Grains pushed past either end are lost [@millerpage_cas].

Three facts follow, and each one generalises:

- **The pile collapses onto a tiny set of states.** Whatever you start with, the pile ends up with at least $N-1$ sites filled, and it stays that way. From then on it is either completely full or has a single gap somewhere. That is $N+1$ possible states out of $2^N$. With $N=30$, more than a billion possible configurations shrink to thirty-one. This is *self-organisation* in its plainest form: the dynamics find a small attractor without anyone steering them [@millerpage_cas].
- **Avalanche sizes can be counted exactly.** Drop a grain into a run of $M$ filled sites, landing $d$ sites in from the nearer end. Two waves of toppling travel outward, reflect off the empty boundaries and cancel when they meet, for a total of $d(M-d+1)$ topples. With $N=10$ and a full pile, a grain on the edge topples 10 sites and a grain in the middle topples 30. Miller & Page's exact long-run distribution matches a 100,000-grain simulation to the first decimal [@millerpage_cas].
- **The tail is fat, but this pile is not a perfect power law.** Every avalanche size has the form $d(M-d+1)$, so some sizes can never occur (no prime size above 10, for example). The distribution has heavy tails, but its exact shape is jagged [@millerpage_cas]. A fat tail and a power law are not the same claim. The [power-laws entry](power-laws-and-scaling.qmd) explains why that distinction matters when you fit data.

The model also explains a pattern people notice in real cascades: **a huge avalanche is followed by small ones.** The size-30 avalanche happens only when the pile is full and the grain lands in the centre. It leaves the gap in the middle, where the largest avalanche still possible is size 9. Big releases use up the sites that were near the threshold, so the system has to rebuild before it can produce another big one [@millerpage_cas].

## The forest-fire model: criticality as a trade-off

Miller & Page's second workhorse is a model of trees on a ridge. Each spring, every empty site sprouts a tree with probability $g$. Each summer, every site is struck by lightning with probability $f$, and a struck tree burns along with **every tree joined to it**. Empty sites act as firebreaks. Measure the forest's **production** as the trees still standing at the end of summer [@millerpage_cas].

Two forces pull against each other. Faster growth means more trees. But more trees also form **longer joined stands**, and one strike can bring down a whole stand. On a ridge of 100 sites with $f=0.02$, production peaks at a growth rate of about 43% (58.5 trees) and falls off on both sides. At $g=1$ the ridge is one solid stand, so the first strike clears it [@millerpage_cas]. On a two-dimensional grid, the same trade-off becomes a sharp **phase transition**. Percolation theory gives a critical growth rate at which scattered clumps of trees suddenly join into one forest-spanning cluster [@millerpage_cas]. This is the same transition as the [giant component of a random graph](random-graphs-erdos-renyi.qmd).

Now add selection. Suppose many forests, each with its own fixed $g$, compete, and the less productive ones are replaced. Because the production curve has a single peak, almost any search method drives the forests to the optimal growth rate. Miller & Page's point is that this means **adaptation leads the system to a precipice.** The most productive growth rate sits right at the critical value, where small deviations cost the most yield, so the system ends up "both optimal and fragile" [@millerpage_cas]. In two or more dimensions the effect is stronger [@millerpage_cas]. This gives an *economic* reason why systems might sit near criticality, alongside the physicist's self-tuning sandpile. Selection for performance can push a system to the edge.

## When the agents can adapt: firewalls and the escape from criticality

Next, Miller & Page let every *site* set its own growth rate. They start each site at a random rate and adjust it with a simple counterfactual check. If a tree here *would have burned*, the site lowers its growth rate; otherwise it raises it [@millerpage_cas]. The results surprised them:

- The average growth rate first **falls** well below the 43% optimum, then rises and settles near **59%**, above it. Production also climbs past the uniform optimum, to **over 65%** against the earlier best of 58.5% [@millerpage_cas].
- The reason is spatial. The ridge sorts itself into **stands of high-growth sites separated by sites whose growth rate has fallen to zero.** In their sample of eleven sites the rates are 1.00, 1.00, 0.00, 1.00, 1.00, 0.99, 0.00, 0.01, 0.99, 1.00, 1.00. The system has grown **firewalls**, with no plan and no intention. Miller & Page cite Adam Smith's invisible hand and call it an example of emergence [@millerpage_cas].
- The firewalls are **unfair**. The sites that end up as firewalls are the most exposed ones, sitting between two fire-prone stands. The adaptive rule drives their growth rate to zero while it rewards their neighbours. They provide the whole ridge's protection and keep none of the benefit. A *far-sighted* firewall could set its rate to one and push the job onto a neighbour [@millerpage_cas].

Smarter agents do not necessarily do better. If agents model their neighbours and each tries hard to grow a tree rather than serve as a firewall, the system can get stuck in "a perpetual muck in which too many trees are chasing too few fire walls." Miller & Page compare this to *simulated annealing*: allowing some mistakes, especially cheap ones made early, helps a system escape poor outcomes. "Less perfection is often more" [@millerpage_cas]. With **omniscient** agents, they conjecture that the most productive layout is a symmetric pattern of **six-tree stands separated by single firewalls**. The adaptive forest gets only part of the way there: its stands vary from one to six trees, sometimes separated by double firewalls [@millerpage_cas].

**The right panel of @fig-sandpile** runs the fixed-rule ridge again by hand and compares it with a firewall design. Under single firewalls with $g=1$, a stand of $k$ trees survives a summer with probability $(1-f)^k$. Our own arithmetic gives about **76 trees per 100 sites** for stands of six. Stands of seven are almost exactly tied with six. The figure shows how far a designed layout beats the best uniform growth rate. It does **not** re-run Miller & Page's adaptive model, since the text does not give the step size of their adaptation rule.

What makes this matter for social science is Miller & Page's own conclusion. With adaptive agents, **the system "configures itself in a way that mitigates the overall risk by preventing criticality from emerging."** That depends on **stable neighbourhoods**: firewalls form only because a site keeps the same risky neighbours from one season to the next. If locations were reshuffled every day, the structure would never form. Miller & Page suggest that banks and suburban neighbourhoods, which have stable relationships, can develop firewalls, while the more transient ties of urban neighbourhoods and highway traffic may not [@millerpage_cas].

The same machinery can be relabelled. Treat trees as **risky loans**, adjacency as **correlated exposure between banks**, lightning as **defaults** and regrowth as **new lending**, and the forest becomes a model of **bank-failure cascades**. Miller & Page cite the 1997 Southeast Asian crisis and the Federal Reserve's 1998 organisation of a \$3.5 billion rescue of Long-Term Capital Management [@millerpage_cas]. A model of people who move to the city, join their kin and flee back to the country after anyone they know is mugged turns out to be the **same model** under different labels [@millerpage_cas].

Even the sandpile changes when its grains have purposes. Suppose each falling agent can choose where to land and knows what avalanche it will cause. Agents who want *small* avalanches alternate between sizes 10 and 0, an average of 5. Agents who myopically want the *largest* avalanche get stuck in a two-cycle of 16 and 12, an average of 14. A cooperative cycle (30, then refill the hole) would average 15. With enough foresight, purposeful agents can produce almost any avalanche distribution they like [@millerpage_cas].

## Is the social world critical? A short checklist

Power laws are real in social data. Miller & Page cite **Richardson's** counts of war deaths, 1820–1945: each tenfold drop in deaths roughly triples the number of wars, which fits $W \approx 6517\,D^{-1/2}$ fairly well. City size against rank follows roughly $P_i = c/R_i$ [@millerpage_cas]. Mistaking a fat-tailed process for a Normal one makes you **grossly underestimate extremes** and dismiss the ones that happen as freak anomalies [@millerpage_cas]. But SOC is only **one** route to a power law. **Simon's** model, in which a city's chance of attracting the next resident is proportional to its size, also produces one with no criticality at all [@millerpage_cas]. Miller & Page find SOC plausible for forest fires, earthquakes, mudslides and floods, and *perhaps* for riots, traffic jams and blackouts. City sizes and word frequencies "probably come from very different generative mechanisms" [@millerpage_cas].

So before claiming a social system is self-organised critical, ask three things. Is there a **slow build-up and fast release** through local contagion? Is the system **fixed-rule**, or do its agents adapt to the cascades they experience? And are neighbourhoods **stable enough** for adaptive firewalls to form?

## Tipping points and early warnings

SOC supplies a *mechanism* for **tipping points** — the moments when a system flips abruptly from one regime to another (a lake turning turbid, a market crashing, an ice sheet collapsing). As a system drifts toward such a critical transition, it shows a detectable fingerprint called **critical slowing down**: the stabilising feedbacks that pull it back from disturbances **weaken**, so it takes **longer and longer to recover** from small perturbations, and its fluctuations grow more correlated [@mitchell_complexity]. This slowing recovery — measurable as rising autocorrelation and variance in a time series — has been proposed as a generic **early-warning signal** of approaching tipping points in ecosystems, climate, and financial markets [@mitchell_complexity].

The promise is real but so is the difficulty: the signal is noisy, it can appear without a transition following, and a transition can arrive with little warning. SOC is a powerful lens, not a crystal ball.

## Common pitfalls

::: {.callout-warning title="Where this goes wrong"}
- **Demanding a big cause for a big event.** In a critical system the trigger of the giant avalanche is the same ordinary grain that usually does nothing — looking for a proportionate cause is a category error. [@mitchell_complexity]
- **Assuming criticality must be tuned.** The whole point of SOC is that the critical state is an *attractor* — the system finds it without anyone setting a dial. [@mitchell_complexity]
- **Treating early-warning signals as guarantees.** Critical slowing down is a statistical tendency, not a deterministic alarm; false positives and silent transitions both occur. [@mitchell_complexity]
- **Over-extending the sandpile.** SOC is a compelling *candidate* mechanism for many power laws, not a proof that any particular one is self-organised critical — that still needs the data. [@mitchell_complexity] Proportional growth (Simon's city model) produces power laws with no criticality at all. [@millerpage_cas]
- **Treating fixed-rule results as if they held for adaptive agents.** Sand cannot learn from avalanches; banks, firms and households can. In the forest-fire model, adaptive sites build firewalls that **steer the system away from criticality**, and purposeful sandpile agents can produce almost any avalanche distribution. Whether a social system is critical depends on whether its agents adapt and whether their neighbourhoods are stable. [@millerpage_cas]
- **Averaging away the structure.** Miller & Page note that standard approximations of the forest-fire model, which work only with the *expected* rates of growth and fire, describe its statistics poorly. Lightning carves the ridge into coherent clusters of trees and bare ground, and averaging throws that clustering away. [@millerpage_cas]
:::

## Appendix · the mathematics {.unnumbered}

::: {.math-appendix}

**The abelian sandpile (BTW).** On a grid, each site $i$ holds height $z_i$. The toppling rule is: if $z_i \ge z_c$ (here $z_c=4$, the number of neighbours), then $z_i \to z_i - 4$ and each neighbour gains one grain. Grains at the boundary leave the system (open boundary), which is what lets the pile reach a *stationary* critical state rather than filling up. The model is "abelian" because the final stable configuration is **independent of the order** in which unstable sites are toppled — a deep property that makes the dynamics well-defined.

**Why a power law.** At the critical state the system has no characteristic length: the spatial extent of toppling activity is correlated across all scales (a diverging correlation length, exactly as at an equilibrium critical point). The avalanche-size distribution then takes the scale-free form
$$
P(s) \sim s^{-\tau} f(s/s_{\max}),
$$
a power law with exponent $\tau$ (near $1$ for the 2-D BTW pile) cut off only by the finite system size $s_{\max}$. See [power laws & scaling](power-laws-and-scaling.qmd) for the statistics of such distributions.

**The minimalist sandpile's avalanche count.** Sites hold 0 or 1 grain; a second grain topples a site, sending one grain to each neighbour. Drop a grain into a block of $M$ filled sites bounded by empty sites (or the edges), $d$ sites in from the nearer boundary. Two toppling fronts move one site per step. Over the first $d$ steps $1,2,\dots,d$ sites topple. For the next $M-2d$ steps, $d$ sites topple per step. The last $d$ steps mirror the first. In total
$$
2\cdot\frac{d(d+1)}{2} + d\,(M-2d) \;=\; d\,(M-d+1),
$$
and the expression is symmetric in $d \leftrightarrow M-d+1$ [@millerpage_cas]. In the long run the pile cycles uniformly through its $N+1$ states, so the avalanche distribution is a simple count over landing sites and states.

**Firewalls, by arithmetic.** On a ridge where stands of $k$ trees ($g=1$) alternate with single empty sites ($g=0$), each stand burns in a summer with probability $1-(1-f)^k$. The expected number of trees standing per site is
$$
\pi(k) = \frac{k}{k+1}\,(1-f)^k .
$$
With $f=0.02$: $\pi(5)\approx0.753$, $\pi(6)\approx0.759$, $\pi(7)\approx0.760$, $\pi(8)\approx0.756$. The curve is very flat near its top. Miller & Page conjecture that stands of six are optimal on their ridge [@millerpage_cas]. In this edge-free calculation, six and seven are effectively tied, and both far exceed the best uniform growth rate (≈ 0.59).

**Critical slowing down.** Near a critical transition the dominant eigenvalue of the system's linearised recovery dynamics approaches $1$ (discrete time) or $0$ (continuous time). The recovery rate $\to 0$, so the return time after a perturbation diverges; in observable terms the **lag-1 autocorrelation $\to 1$** and the **variance rises**. These are the statistical early-warning indicators.

:::
