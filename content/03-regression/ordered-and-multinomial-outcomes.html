Ordered & Multinomial Outcomes: More Than Two Categories

  • Show All Code
  • Hide All Code
  • View Source

When the outcome is a ranking (Low/Medium/High) or an unranked menu (car/bus/train), binary logit splits in two directions — one that keeps the order, one that doesn’t.

Binary logit handles yes/no. But many outcomes have three or more categories — a performance band (Bottom/Middle/Top), a Likert rating, a mode of transport, a chosen health plan. Two extensions carry logit across the gap: ordered logit, which honours a ranking with one slope and a set of cut-points, and multinomial logit, which treats the categories as an unranked menu and fits a separate contrast for each. Choosing between them is really one question — does the order carry information you should keep?

Why it matters

A great deal of social-science data is categorical with more than two levels. Survey answers on a 1–5 scale; credit ratings; job-satisfaction bands; the plan an employee picks; the candidate a voter chooses. The temptation is to reach for a tool you already own: run OLS on the numbers 1–5, or collapse to a binary and run plain logit. Both throw information away. Putting a raw ordinal outcome into a linear regression implicitly assumes the gaps between levels are equal and cardinal — that the step from “Low” to “Medium” is worth exactly as much as “Medium” to “High” — which is precisely what an ordinal scale refuses to promise. (Wooldridge 2019) Collapsing to binary discards the ordering wholesale and requires an arbitrary cut. (Wooldridge 2019) The right tools sit one step past binary logit: they keep the categories intact and, when the outcome is ranked, keep the ranking too.

Two kinds of many-category outcome

The fork is the whole decision:

  • Ordered — the categories have a natural sequence: Bottom < Middle < Top; Disagree < Neutral < Agree; Junk < Investment-grade. The distances between them are unknown, but the order is real and informative. Use ordered logit (a.k.a. proportional-odds or ordinal logistic regression).
  • Nominal / unordered — the categories are a menu with no ranking: car / bus / train; health-plan A / B / C; chosen major. There is no sense in which one is “more” than another. Use multinomial logit.

Getting the fork wrong is a real error. Treat an ordered outcome as nominal and you throw away the ordering — burning degrees of freedom on contrasts the data could have pooled. Treat a nominal outcome as ordered and you invent a ranking that isn’t there. (McNulty 2021)

Ordered logit: slice a latent scale with cut-points

The cleanest way to see ordered logit is the latent-variable story you already met for binary logit, extended by more than one threshold. Imagine an unobserved propensity y^* = x\beta + e — an underlying “amount” of the thing (satisfaction, performance, creditworthiness). You don’t observe y^*; you observe which band it falls into, carved out by a set of ordered cut-points c_1 < c_2 < \cdots < c_{K-1}: (McNulty 2021)

Y = \begin{cases} 1 \ (\text{Low}) & \text{if } y^* \le c_1,\\ 2 \ (\text{Middle}) & \text{if } c_1 < y^* \le c_2,\\ 3 \ (\text{Top}) & \text{if } y^* > c_2. \end{cases}

Equivalently — and this is McNulty’s framing — an ordered model is a stack of cumulative binary questions sharing one slope: (McNulty 2021)

\ln\!\left(\frac{P(Y \le k)}{P(Y > k)}\right) = c_k - x\beta, \qquad k = 1, \dots, K-1.

Every cut-point k gets its own intercept c_k (where the boundary sits), but there is one shared slope \beta for each predictor across all the cut-points. That single-slope constraint is the heart of the model, and it has a name: the proportional-odds assumption. It says a predictor moves the odds of being above any given threshold by the same multiplicative factor, no matter which threshold — so on the cumulative-logit scale the curves for P(Y\le 1), P(Y\le 2), … are parallel, differing only by a horizontal shift.

Show the figure code 
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(11)
n = 4000
beta = 1.2
c1, c2 = -1.0, 1.4                    # cut-points on the latent scale
x = rng.uniform(-3, 3, n)
ystar = beta * x + rng.logistic(0.0, 1.0, n)   # latent propensity, logistic noise
y = np.ones(n, dtype=int)
y[ystar > c1] = 2
y[ystar > c2] = 3

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))

xs = np.linspace(-3, 3, 200)
P_le1 = sigmoid(c1 - beta * xs)      # P(Y <= Low)
P_le2 = sigmoid(c2 - beta * xs)      # P(Y <= Middle)

# empirical cumulative proportions in quantile bins of x
edges = np.quantile(x, np.linspace(0, 1, 13))
centers, e1, e2 = [], [], []
for lo, hi in zip(edges[:-1], edges[1:]):
    m = (x >= lo) & (x < hi)
    if m.sum() < 20:
        continue
    centers.append(x[m].mean())
    e1.append(np.mean(y[m] <= 1))
    e2.append(np.mean(y[m] <= 2))
centers = np.array(centers)

fig, ax = plt.subplots(figsize=(7, 4.2))
ax.scatter(centers, e1, s=28, color="#b7b6a8", zorder=3)
ax.scatter(centers, e2, s=28, color="#5e5e54", zorder=3)
ax.plot(xs, P_le1, color="#161613", lw=2.4, label=r"$P(Y \leq \mathrm{Low})$")
ax.plot(xs, P_le2, color="#161613", lw=2.4, ls="--", label=r"$P(Y \leq \mathrm{Middle})$")

gap = (c2 - c1) / beta               # constant horizontal shift between the curves
for p in (0.3, 0.7):
    lg = np.log(p / (1 - p))
    xa = (c1 - lg) / beta
    ax.annotate("", xy=(xa + gap, p), xytext=(xa, p),
                arrowprops=dict(arrowstyle="<->", color="#e8531d", lw=1.8))
ax.text(0.1, 0.5, "equal horizontal shift\n(same slope = proportional odds)",
        color="#e8531d", fontsize=8.5, ha="left", va="center")

ax.set_ylim(-0.03, 1.03)
ax.set_xlabel("predictor x")
ax.set_ylabel(r"cumulative probability  $P(Y \leq k)$")
ax.set_title("Proportional odds: two parallel cumulative-logit curves")
ax.legend(fontsize=9, frameon=False, loc="lower right")
fig.tight_layout()
plt.show()

Reading the coefficients

Because ordered logit is built from log-odds, its coefficients interpret exactly like binary logit’s: exponentiate to get an odds ratio, here the multiplier on the odds of landing in a higher category rather than a lower one, per one-unit rise in the predictor (all else equal). (McNulty 2021) From McNulty’s fictional managers data — modelling a performance band (Bottom/Middle/Top) on test score, group size, and years employed:

  • an extra point on the manager test multiplies the odds of a higher band by e^{0.0043}\approx 1.004 — about 0.4% per point;
  • each additional person in the group, e^{0.092}\approx 1.10 — about 10% higher odds;
  • each additional year employed, e^{-0.883}\approx 0.41 — the odds of a higher band fall by ~59%. (McNulty 2021)

As with binary logit, the coefficient is a statement about odds, not probability, and it is not the marginal effect on any single category’s probability — for that you compute predicted probabilities at values of interest. (McNulty 2021)

Checking the proportional-odds assumption

The single-slope constraint is what makes ordered logit parsimonious — and what can make it wrong. If a predictor genuinely acts differently at different thresholds (it separates the top from everyone but barely distinguishes the bottom two), forcing one slope misfits. Two standard checks: (McNulty 2021)

  • Fit the cumulative binaries separately and compare. Collapse the outcome into each binary split (“Bottom vs Middle-or-Top”, then “Bottom-or-Middle vs Top”), run an ordinary logit on each, and line up the slopes. Under proportional odds they should be close; large gaps are a red flag.
  • The Brant test (a.k.a. the parallel-regression or Wald test) formalises this with a chi-square: a low p-value signals that a coefficient violates the assumption. (McNulty 2021)

When the assumption fails, you relax it — a partial or generalized ordered logit lets the offending predictor take its own slope per threshold while the rest stay pooled; or, if the ordering buys you little, fall back to multinomial logit.

Multinomial logit: one contrast per category

When the categories have no order, there is nothing to keep parallel. Multinomial logit picks one category as the reference (base) and fits a separate binary-logit-style equation for every other category against that base: (McNulty 2021)

\ln\!\left(\frac{P(Y = k)}{P(Y = \text{base})}\right) = x\beta_k, \qquad k \ne \text{base}.

So a model with p predictors and K categories estimates (K-1)\times p slopes — each non-reference category carries its own coefficient vector. If health plans A, B, C are the menu and A is the base, one equation explains choosing B-over-A and another C-over-A; the coefficient on “salary” in the B equation is how salary shifts the log-odds of B relative to A, saying nothing directly about C. (McNulty 2021) Exponentiated, each is a relative-risk ratio. Solving the equations for the probabilities themselves gives the softmax form, P(Y=k) = e^{x\beta_k} / \sum_j e^{x\beta_j} (with \beta_{\text{base}}=0) — the very same function that turns a neural network’s scores into class probabilities in the ML track.

Multinomial logit is flexible but pays for it two ways. It spends many more parameters than ordered logit (a K-category, p-predictor model has (K-1)p slopes versus ordered logit’s p), and it leans on the independence of irrelevant alternatives (IIA) assumption: the odds of car-versus-bus shouldn’t depend on whether a train is also on the menu. The classic failure is the red-bus/blue-bus problem — add a second bus identical but for colour, and a model that assumes IIA absurdly steals share from the car rather than only from the other bus. When IIA is untenable, richer discrete-choice models (nested logit, mixed/random-parameters logit, multinomial probit) are the escape.

Common pitfalls

WarningWhere this goes wrong

  • Running OLS on an ordinal outcome. Regressing on the codes 1–5 assumes the gaps are equal and cardinal — that “Agree − Neutral” equals “Neutral − Disagree.” An ordinal scale makes no such promise; use ordered logit. (Wooldridge 2019)

  • Collapsing an ordered outcome to binary “to keep it simple.” You discard the ordering and pick an arbitrary cut, throwing away information the ordinal model would use. (Wooldridge 2019)

  • Treating an ordered outcome as nominal (multinomial). It “works,” but wastes degrees of freedom on contrasts the ordering could have pooled — and gives up the single-slope interpretability. (McNulty 2021)

  • Never checking proportional odds. The shared slope is an assumption, not a fact. Compare the separate cumulative binaries or run a Brant test; if it fails, relax to a partial/generalized ordered logit. (McNulty 2021)

  • Reading coefficients as probabilities. As in binary logit, ordered- and multinomial-logit coefficients are on the log-odds scale. Report odds/relative-risk ratios, and compute predicted probabilities for the effect that actually matters. (McNulty 2021)

  • Forgetting the reference category in multinomial output. Every coefficient is relative to the base; a positive coefficient for B doesn’t mean B is likely in absolute terms, only more likely than the base.

  • Trusting multinomial logit when IIA fails — the red-bus/blue-bus trap. If adding or removing an alternative would plausibly reshuffle the other odds, move to nested or mixed logit.

  • Treating any of these coefficients as causal. Everything from what regression can and can’t tell you still applies — a precise logit coefficient on an endogenous regressor is still a biased effect.

From the sources

NoteWho says what
  • McNulty, Explanatory Statistical Modeling in R — the model-choice map keyed to outcome scale (continuous → linear; binary → binomial logit; nominal → multinomial; ordinal → ordinal logistic); ordered logit as a stack of cumulative binaries sharing one slope with per-cut-point intercepts; the odds-ratio reading of coefficients (the managers example — test-score OR ≈1.004, group-size ≈1.10, years-employed ≈0.41); the proportional-odds assumption and its two checks (compare separately-fitted cumulative binaries; the Brant parallel-regression test); multinomial logit as reference-category log-odds with a separate coefficient vector per category (the health-plan A/B/C example); polr() and glm()/multinom() machinery.
  • Wooldridge, Introductory Econometrics — why a raw ordinal outcome doesn’t belong in OLS (coefficients hard to interpret; a unit change in an ordinal code has no cardinal meaning); ordered logit and ordered probit as the tools for ordered responses, extending binary logit/probit; the crude binary-collapse alternative and its information loss; and the parallel point that ordinal regressors are best entered as a dummy set.

Appendix · the mathematics

Ordered logit from the latent variable. Let y^* = x\beta + e with e logistic (CDF \Lambda(z)=1/(1+e^{-z})), and observe Y=k when c_{k-1} < y^* \le c_k (with c_0=-\infty, c_K=+\infty). Then the cumulative probability is P(Y \le k \mid x) = P(y^* \le c_k) = \Lambda(c_k - x\beta), a single S-curve per cut-point, all sharing the slope -\beta — hence parallel on the logit scale (proportional odds). Individual category probabilities are differences of neighbours, P(Y = k \mid x) = \Lambda(c_k - x\beta) - \Lambda(c_{k-1} - x\beta), which are automatically non-negative because the cut-points are ordered. Swapping \Lambda for the Normal CDF \Phi gives ordered probit.

Multinomial logit (softmax). Fix a base category with \beta_{\text{base}}=0. For each k, \ln\!\big(P(Y=k)/P(Y=\text{base})\big) = x\beta_k, and normalising so the probabilities sum to one gives P(Y = k \mid x) = \frac{e^{x\beta_k}}{\sum_{j} e^{x\beta_j}}. The relative-risk ratio e^{\beta_{k,\ell}} is the multiplier on the odds of category k versus the base per unit rise in predictor \ell. IIA is visible here: the ratio P(Y=k)/P(Y=m) = e^{x(\beta_k-\beta_m)} does not involve any third category’s parameters — the modelling assumption made explicit.

Estimation. Both are nonlinear in the parameters and fit by maximum likelihood: the log-likelihood sums \log P(Y=y_i\mid x_i) over observations, with the category probabilities above, and is maximised numerically. The estimates are consistent and asymptotically Normal, so the usual z-style inference applies — exactly the machinery of binary logit, one dimension larger.

\end{cases}
$$

Equivalently — and this is McNulty's framing — an ordered model is a **stack of cumulative binary
questions** sharing one slope: [@mcnulty_rmodeling]

$$
\ln\!\left(\frac{P(Y \le k)}{P(Y > k)}\right) = c_k - x\beta, \qquad k = 1, \dots, K-1.
$$

Every cut-point $k$ gets its **own intercept** $c_k$ (where the boundary sits), but there is **one
shared slope** $\beta$ for each predictor across *all* the cut-points. That single-slope constraint is
the heart of the model, and it has a name: the **proportional-odds assumption**. It says a predictor
moves the odds of being *above* any given threshold by the same multiplicative factor, no matter which
threshold — so on the cumulative-logit scale the curves for $P(Y\le 1)$, $P(Y\le 2)$, … are **parallel**,
differing only by a horizontal shift.

```{python}
#| label: fig-proportional-odds
#| fig-cap: "An ordered outcome (Low/Middle/Top) simulated from a single latent scale cut at two thresholds. Dots are the empirical cumulative proportions P(Y ≤ Low) and P(Y ≤ Middle) in bins of x; the ink curves are the fitted cumulative-logit model. The proportional-odds assumption forces the two curves to share one slope — so they are parallel, separated by a constant horizontal shift (orange). That shared slope is exactly the single coefficient β the model reports per predictor; the two intercepts are the cut-points."
#| code-fold: true
#| code-summary: "Show the figure code"

import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(11)
n = 4000
beta = 1.2
c1, c2 = -1.0, 1.4                    # cut-points on the latent scale
x = rng.uniform(-3, 3, n)
ystar = beta * x + rng.logistic(0.0, 1.0, n)   # latent propensity, logistic noise
y = np.ones(n, dtype=int)
y[ystar > c1] = 2
y[ystar > c2] = 3

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))

xs = np.linspace(-3, 3, 200)
P_le1 = sigmoid(c1 - beta * xs)      # P(Y <= Low)
P_le2 = sigmoid(c2 - beta * xs)      # P(Y <= Middle)

# empirical cumulative proportions in quantile bins of x
edges = np.quantile(x, np.linspace(0, 1, 13))
centers, e1, e2 = [], [], []
for lo, hi in zip(edges[:-1], edges[1:]):
    m = (x >= lo) & (x < hi)
    if m.sum() < 20:
        continue
    centers.append(x[m].mean())
    e1.append(np.mean(y[m] <= 1))
    e2.append(np.mean(y[m] <= 2))
centers = np.array(centers)

fig, ax = plt.subplots(figsize=(7, 4.2))
ax.scatter(centers, e1, s=28, color="#b7b6a8", zorder=3)
ax.scatter(centers, e2, s=28, color="#5e5e54", zorder=3)
ax.plot(xs, P_le1, color="#161613", lw=2.4, label=r"$P(Y \leq \mathrm{Low})$")
ax.plot(xs, P_le2, color="#161613", lw=2.4, ls="--", label=r"$P(Y \leq \mathrm{Middle})$")

gap = (c2 - c1) / beta               # constant horizontal shift between the curves
for p in (0.3, 0.7):
    lg = np.log(p / (1 - p))
    xa = (c1 - lg) / beta
    ax.annotate("", xy=(xa + gap, p), xytext=(xa, p),
                arrowprops=dict(arrowstyle="<->", color="#e8531d", lw=1.8))
ax.text(0.1, 0.5, "equal horizontal shift\n(same slope = proportional odds)",
        color="#e8531d", fontsize=8.5, ha="left", va="center")

ax.set_ylim(-0.03, 1.03)
ax.set_xlabel("predictor x")
ax.set_ylabel(r"cumulative probability  $P(Y \leq k)$")
ax.set_title("Proportional odds: two parallel cumulative-logit curves")
ax.legend(fontsize=9, frameon=False, loc="lower right")
fig.tight_layout()
plt.show()
```

### Reading the coefficients

Because ordered logit is built from log-odds, its coefficients interpret **exactly like binary logit's**:
exponentiate to get an **odds ratio**, here the multiplier on the odds of landing in a *higher* category
rather than a lower one, per one-unit rise in the predictor (all else equal). [@mcnulty_rmodeling] From
McNulty's fictional **managers** data — modelling a performance band (Bottom/Middle/Top) on test score,
group size, and years employed:

- an extra point on the manager test multiplies the odds of a higher band by $e^{0.0043}\approx 1.004$
  — about **0.4% per point**;
- each additional person in the group, $e^{0.092}\approx 1.10$ — about **10% higher odds**;
- each additional year employed, $e^{-0.883}\approx 0.41$ — the odds of a higher band **fall by ~59%**.
  [@mcnulty_rmodeling]

As with binary logit, the coefficient is a statement about *odds*, not probability, and it is **not** the
marginal effect on any single category's probability — for that you compute predicted probabilities at
values of interest. [@mcnulty_rmodeling]

### Checking the proportional-odds assumption

The single-slope constraint is what makes ordered logit parsimonious — and what can make it *wrong*. If a
predictor genuinely acts differently at different thresholds (it separates the top from everyone but
barely distinguishes the bottom two), forcing one slope misfits. Two standard checks: [@mcnulty_rmodeling]

- **Fit the cumulative binaries separately** and compare. Collapse the outcome into each binary split
  ("Bottom vs Middle-or-Top", then "Bottom-or-Middle vs Top"), run an ordinary logit on each, and line up
  the slopes. Under proportional odds they should be *close*; large gaps are a red flag.
- **The Brant test** (a.k.a. the parallel-regression or Wald test) formalises this with a chi-square: a
  **low** p-value signals that a coefficient violates the assumption. [@mcnulty_rmodeling]

When the assumption fails, you relax it — a **partial** or **generalized** ordered logit lets the
offending predictor take its own slope per threshold while the rest stay pooled; or, if the ordering
buys you little, fall back to multinomial logit.

## Multinomial logit: one contrast per category

When the categories have **no order**, there is nothing to keep parallel. Multinomial logit picks one
category as the **reference** (base) and fits a separate binary-logit-style equation for every other
category *against that base*: [@mcnulty_rmodeling]

$$
\ln\!\left(\frac{P(Y = k)}{P(Y = \text{base})}\right) = x\beta_k, \qquad k \ne \text{base}.
$$

So a model with $p$ predictors and $K$ categories estimates $(K-1)\times p$ slopes — **each non-reference
category carries its own coefficient vector**. If health plans A, B, C are the menu and A is the base, one
equation explains choosing B-over-A and another C-over-A; the coefficient on "salary" in the B equation is
how salary shifts the log-odds of B *relative to A*, saying nothing directly about C. [@mcnulty_rmodeling]
Exponentiated, each is a **relative-risk ratio**. Solving the equations for the probabilities themselves
gives the **softmax** form, $P(Y=k) = e^{x\beta_k} / \sum_j e^{x\beta_j}$ (with $\beta_{\text{base}}=0$) —
the very same function that turns a neural network's scores into class probabilities in
[the ML track](../ml-track/generative-classifiers.qmd).

Multinomial logit is flexible but pays for it two ways. It **spends many more parameters** than ordered
logit (a $K$-category, $p$-predictor model has $(K-1)p$ slopes versus ordered logit's $p$), and it leans on
the **independence of irrelevant alternatives (IIA)** assumption: the odds of car-versus-bus shouldn't
depend on whether a *train* is also on the menu. The classic failure is the **red-bus/blue-bus** problem —
add a second bus identical but for colour, and a model that assumes IIA absurdly steals share from the car
rather than only from the other bus. When IIA is untenable, richer discrete-choice models (nested logit,
mixed/random-parameters logit, multinomial probit) are the escape.

## Common pitfalls

::: {.callout-warning title="Where this goes wrong"}

- **Running OLS on an ordinal outcome.** Regressing on the codes 1–5 assumes the gaps are equal and
  cardinal — that "Agree − Neutral" equals "Neutral − Disagree." An ordinal scale makes no such promise;
  use ordered logit. [@wooldridge_intro]

- **Collapsing an ordered outcome to binary "to keep it simple."** You discard the ordering and pick an
  arbitrary cut, throwing away information the ordinal model would use. [@wooldridge_intro]

- **Treating an ordered outcome as nominal (multinomial).** It "works," but wastes degrees of freedom on
  contrasts the ordering could have pooled — and gives up the single-slope interpretability.
  [@mcnulty_rmodeling]

- **Never checking proportional odds.** The shared slope is an *assumption*, not a fact. Compare the
  separate cumulative binaries or run a Brant test; if it fails, relax to a partial/generalized ordered
  logit. [@mcnulty_rmodeling]

- **Reading coefficients as probabilities.** As in [binary logit](limited-dependent-variables.qmd),
  ordered- and multinomial-logit coefficients are on the **log-odds** scale. Report odds/relative-risk
  ratios, and compute predicted probabilities for the effect that actually matters. [@mcnulty_rmodeling]

- **Forgetting the reference category in multinomial output.** Every coefficient is *relative to the base*;
  a positive coefficient for B doesn't mean B is likely in absolute terms, only more likely than the base.

- **Trusting multinomial logit when IIA fails** — the red-bus/blue-bus trap. If adding or removing an
  alternative would plausibly reshuffle the *other* odds, move to nested or mixed logit.

- **Treating any of these coefficients as causal.** Everything from
  [what regression can and can't tell you](regression-and-causality.qmd) still applies — a precise logit
  coefficient on an endogenous regressor is still a biased effect.

:::

## From the sources {.unnumbered}

::: {.callout-note collapse="true" title="Who says what"}
- **McNulty, *Explanatory Statistical Modeling in R*** — the model-choice map keyed to outcome scale
  (continuous → linear; binary → binomial logit; nominal → multinomial; ordinal → ordinal logistic);
  ordered logit as a stack of cumulative binaries sharing one slope with per-cut-point intercepts; the
  odds-ratio reading of coefficients (the managers example — test-score OR ≈1.004, group-size ≈1.10,
  years-employed ≈0.41); the proportional-odds assumption and its two checks (compare separately-fitted
  cumulative binaries; the Brant parallel-regression test); multinomial logit as reference-category
  log-odds with a separate coefficient vector per category (the health-plan A/B/C example); `polr()` and
  `glm()`/`multinom()` machinery.
- **Wooldridge, *Introductory Econometrics*** — why a raw ordinal outcome doesn't belong in OLS
  (coefficients hard to interpret; a unit change in an ordinal code has no cardinal meaning); ordered
  logit and ordered probit as the tools for ordered responses, extending binary logit/probit; the crude
  binary-collapse alternative and its information loss; and the parallel point that ordinal *regressors*
  are best entered as a dummy set.

## Appendix · the mathematics {.unnumbered}

::: {.math-appendix}

**Ordered logit from the latent variable.** Let $y^* = x\beta + e$ with $e$ logistic (CDF
$\Lambda(z)=1/(1+e^{-z})$), and observe $Y=k$ when $c_{k-1} < y^* \le c_k$ (with $c_0=-\infty$,
$c_K=+\infty$). Then the **cumulative** probability is
$$
P(Y \le k \mid x) = P(y^* \le c_k) = \Lambda(c_k - x\beta),
$$
a single S-curve per cut-point, all sharing the slope $-\beta$ — hence *parallel* on the logit scale
(**proportional odds**). Individual category probabilities are **differences of neighbours**,
$$
P(Y = k \mid x) = \Lambda(c_k - x\beta) - \Lambda(c_{k-1} - x\beta),
$$
which are automatically non-negative because the cut-points are ordered. Swapping $\Lambda$ for the Normal
CDF $\Phi$ gives **ordered probit**.

**Multinomial logit (softmax).** Fix a base category with $\beta_{\text{base}}=0$. For each $k$,
$\ln\!\big(P(Y=k)/P(Y=\text{base})\big) = x\beta_k$, and normalising so the probabilities sum to one gives
$$
P(Y = k \mid x) = \frac{e^{x\beta_k}}{\sum_{j} e^{x\beta_j}}.
$$
The relative-risk ratio $e^{\beta_{k,\ell}}$ is the multiplier on the odds of category $k$ versus the base
per unit rise in predictor $\ell$. IIA is visible here: the ratio $P(Y=k)/P(Y=m) = e^{x(\beta_k-\beta_m)}$
does not involve any third category's parameters — the modelling assumption made explicit.

**Estimation.** Both are **nonlinear in the parameters** and fit by
[maximum likelihood](../02-inference/estimation.qmd): the log-likelihood sums $\log P(Y=y_i\mid x_i)$ over
observations, with the category probabilities above, and is maximised numerically. The estimates are
consistent and asymptotically Normal, so the usual z-style [inference](inference-for-regression.qmd)
applies — exactly the machinery of binary logit, one dimension larger.

:::
