Choosing the Right Statistical Test

  • Show All Code
  • Hide All Code
  • View Source

A map from research question to the ideal test — routed by what you’re asking, the type of your outcome, the structure of your data, and the design that produced it. The capstone that ties the inference toolkit together.

There is no such thing as the statistical test — there is the test that matches your question, your outcome variable, the structure of your data, and the design that produced it. Get those four right and the test almost picks itself; get any one wrong and a perfectly executed test answers the wrong question. This page is the map. It routes you from a research question to a test, shows why most of those tests are secretly the same model, and warns where the routing goes wrong.

Why it matters

Beginners memorise a menu of tests and then hunt for one that fits the data in front of them — often after seeing the data, which is how false positives are manufactured. The professional move is the reverse: the test is implied by the question and the design, decided before a single number is computed. Martin & Bridgmon frame the whole enterprise as a pipeline “from hypothesis to results” — the hypothesis and the design determine the analysis, not the other way round (Martin and Bridgmon 2012). This entry makes that routing explicit, and connects it to the deeper truth that nearly every classical test is a special case of regression.

Start with the question, not the test

Every analysis answers one of a small number of question types, and the type is the first fork in the road:

  • Difference — do groups differ on some outcome? (treatment vs control, men vs women)
  • Association — do two variables move together? (education and income)
  • Prediction — can I forecast an outcome from inputs, and how well?
  • Change — did something move over time or condition, within the same units? (before vs after)
  • Agreement — do two measurements or raters concur? (reliability)

Name the question type first. “I want a t-test” is putting the cart before the horse; “I want to know whether two independent groups differ on a continuous outcome” is a two-sample t-test, stated as a question.

The four things that pick the test

Once the question is named, four features of the data settle the test:

  1. Outcome (dependent) variable type — is it continuous (a mean makes sense), binary, nominal (unordered categories), ordinal (ordered), a count, or a time-to-event? This is the single biggest determinant, and it is a question about the level of measurement.
  2. Predictor / grouping structure — how many groups (one, two, three or more), and is the predictor itself categorical or continuous? One continuous predictor points at correlation/regression; a grouping factor points at a group-comparison test.
  3. Dependence structure (the design) — are observations independent, paired/repeated (the same units measured twice or more), or clustered/nested (students in classrooms)? This is set by the study design, and it changes the test even when everything else is identical.
  4. Assumptions — does the outcome look roughly normal with comparable spread across groups, are cells large enough? When these hold, use the parametric test; when they fail, use its nonparametric or resampling counterpart.

The map

Read across from your question and outcome; the design row (independent / paired / clustered) picks between neighbours. Each cell links to its home entry.

Question · outcome Independent groups Paired / repeated Continuous predictor
Difference, continuous t-test (2) · ANOVA (3+) → nonpar: Mann–Whitney / Kruskal–Wallis paired t → Wilcoxon signed-rank; 3+ → mixed / repeated-measures linear regression
Difference, binary / proportion two-proportion z / χ² · Fisher’s exact (small) McNemar’s test logistic regression
Difference, nominal (>2 cat.) χ² of independence — multinomial logit
Difference, count χ² / rate comparison mixed Poisson / negative-binomial
Association, two continuous Pearson r → Spearman if non-linear/ordinal — regression
Prediction / many predictors multiple regression / GLM mixed-effects / fixed effects multiple regression
Time-to-event Kaplan–Meier / log-rank frailty models Cox regression

The rightmost column is the tell: every row ends in a regression. That is not a coincidence.

Every test is a linear model

The reason all roads end in regression: the classical tests are regressions in disguise. A two-sample t-test is a linear regression of the outcome on a single 0/1 group indicator — the slope is the mean difference, and its t-statistic is identical to the t-test’s. One-way ANOVA is regression on a set of group dummies; a paired t-test is a regression with a per-subject intercept; Pearson correlation is the slope of a standardised regression. (Bruce et al. 2020) Seeing this collapses the menu into one idea and tells you when to graduate: the moment you need to adjust for a covariate, the canned test has no slot for it, but the regression does — add a term. Continuous outcome → linear model; binary → logistic; count → Poisson; time-to-event → Cox — the GLM family is the test menu, unified.

Show the figure code 
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
nA, nB = 30, 34
A = rng.normal(5.0, 1.6, nA)
B = rng.normal(6.1, 1.6, nB)

# --- classical pooled two-sample t-test, by hand ---
mA, mB = A.mean(), B.mean()
sp2 = ((nA-1)*A.var(ddof=1) + (nB-1)*B.var(ddof=1)) / (nA + nB - 2)
t_ttest = (mB - mA) / np.sqrt(sp2 * (1/nA + 1/nB))

# --- OLS of y on a 0/1 group dummy, by hand: t on the slope ---
y = np.concatenate([A, B])
x = np.concatenate([np.zeros(nA), np.ones(nB)])
X = np.column_stack([np.ones(len(y)), x])
beta = np.linalg.solve(X.T @ X, X.T @ y)          # [intercept, slope=mB-mA]
resid = y - X @ beta
s2 = resid @ resid / (len(y) - 2)
se_slope = np.sqrt(s2 * np.linalg.inv(X.T @ X)[1, 1])
t_reg = beta[1] / se_slope

fig, (axL, axR) = plt.subplots(1, 2, figsize=(8.6, 4.0),
                               gridspec_kw={"width_ratios": [1.25, 1]})
jit = rng.uniform(-0.06, 0.06, len(y))
axL.scatter(x + jit, y, s=16, color="#5e5e54", alpha=0.8, zorder=2)
xs = np.array([0, 1])
axL.plot(xs, beta[0] + beta[1]*xs, color="#e8531d", lw=2.6, zorder=3,
         label=f"OLS on dummy (slope = {beta[1]:.3f})")
axL.plot([0, 1], [mA, mB], "o", color="#161613", ms=9, zorder=4)
axL.set_xticks([0, 1]); axL.set_xticklabels(["group A", "group B"])
axL.set_ylabel("outcome  y"); axL.set_xlim(-0.35, 1.35)
axL.set_title("Regress y on a 0/1 group indicator", fontsize=10)
axL.legend(fontsize=8, frameon=False, loc="upper left")

axR.axis("off")
axR.text(0.5, 0.78, "same data, two ways", ha="center", fontsize=10, color="#161613", fontweight="bold")
axR.text(0.5, 0.55, f"two-sample t-test\n$t = {t_ttest:.4f}$", ha="center", fontsize=11, color="#5e5e54")
axR.text(0.5, 0.30, f"regression slope\n$t = {t_reg:.4f}$", ha="center", fontsize=11, color="#e8531d")
axR.text(0.5, 0.08, f"identical  (df = {nA+nB-2})", ha="center", fontsize=9.5,
         color="#161613", style="italic")
fig.tight_layout()
plt.show()

assert abs(t_ttest - t_reg) < 1e-10          # the point, guaranteed

The design axis: dependence changes everything

Of the four features, dependence structure is the one beginners drop — and it is the most punishing. Two datasets with identical outcomes and groups demand different tests if one is paired and the other independent, or if observations cluster. Treating clustered data (pupils within schools, repeated measures within a person, patients within a hospital) as if every observation were independent is pseudoreplication: you claim far more independent information than you have, your standard errors shrink to a fiction, and your false-positive rate explodes. The fix is a test that respects the design — aggregate to the cluster, or use a mixed-effects / fixed-effects model. The simulation makes the damage concrete.

Show the figure code 
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
n_sims = 2000
n_clusters = 20            # 10 per arm
per_cluster = 15
icc_sd = 1.0              # cluster-level random effect (creates within-cluster correlation)
noise_sd = 1.0

def one_sim():
    # cluster-level random intercepts; NO true treatment effect (null is true)
    clam = rng.normal(0, icc_sd, n_clusters)
    arm = np.array([0]*(n_clusters//2) + [1]*(n_clusters//2))
    y, g, cmeans_by_arm = [], [], {0: [], 1: []}
    for c in range(n_clusters):
        obs = clam[c] + rng.normal(0, noise_sd, per_cluster)   # no arm term added
        y.append(obs); g.append(np.full(per_cluster, arm[c]))
        cmeans_by_arm[arm[c]].append(obs.mean())
    y = np.concatenate(y); g = np.concatenate(g)

    # naive: pool all obs, two-sample t treating every obs as independent
    def t_stat(a, b):
        na, nb = len(a), len(b)
        sp2 = ((na-1)*a.var(ddof=1) + (nb-1)*b.var(ddof=1)) / (na+nb-2)
        return (b.mean() - a.mean()) / np.sqrt(sp2*(1/na + 1/nb))
    t_naive = t_stat(y[g == 0], y[g == 1])
    # correct: one number per cluster, then t on the 10 vs 10 cluster means
    t_correct = t_stat(np.array(cmeans_by_arm[0]), np.array(cmeans_by_arm[1]))
    return abs(t_naive), abs(t_correct)

res = np.array([one_sim() for _ in range(n_sims)])
crit = 1.96                                   # ~5% two-sided (normal approx)
err_naive = np.mean(res[:, 0] > crit) * 100
err_correct = np.mean(res[:, 1] > crit) * 100

fig, ax = plt.subplots(figsize=(7.2, 4.3))
bars = ax.bar(["naive\n(ignores clustering)", "correct\n(cluster means)"],
              [err_naive, err_correct], color=["#e8531d", "#161613"], width=0.55,
              edgecolor="#161613", linewidth=1.2, zorder=3)
ax.axhline(5, color="#5e5e54", lw=1.4, ls=(0, (4, 3)), zorder=2)
ax.text(1.45, 5, " 5% (correct rate)", color="#3a3a33", fontsize=9, va="bottom", ha="right")
for b, v in zip(bars, [err_naive, err_correct]):
    ax.text(b.get_x() + b.get_width()/2, v + 0.7, f"{v:.0f}%", ha="center",
            fontsize=11, fontweight="bold", color="#161613")
ax.set_ylabel("false-positive rate  (rejections of a true null)")
ax.set_ylim(0, max(err_naive, 10) * 1.2)
ax.set_title("Same null, same data — the naive test invents significance")
fig.tight_layout()
plt.show()

Choose before you look; report the estimand

Two disciplines separate honest test choice from fishing:

  • Decide from the design, before the data. The question and design fix the test in the analysis plan; a test chosen after inspecting the data (trying several, keeping the significant one) has an uncontrolled false-positive rate — the garden of forking paths (Reinhart 2015).
  • The test is not the goal; the estimate is. A p-value answers “signal or noise?” but you almost always want the magnitude — report an effect size and its confidence interval, not just a verdict (Bruce et al. 2020). And size the study with power beforehand, correcting for multiple comparisons if you run many.

Common pitfalls

WarningWhere test choice goes wrong

  • Picking the test after seeing the data. Running a t-test, then a Mann–Whitney, then reporting whichever cleared 0.05, is p-hacking. Choose from the design in advance. (Reinhart 2015)

  • Ignoring dependence. Paired data run as independent (or clustered data pooled as independent) uses the wrong standard error — the simulation above shows false positives exploding. Match the test to the design.

  • Forcing a mean onto the wrong scale. A t-test on an ordinal 1–5 rating, or on a heavily skewed outcome, can mislead; use a rank-based or nonparametric test, or model the scale properly. Levels of measurement constrain what is meaningful. (Martin and Bridgmon 2012)

  • Reaching for a canned test when you need a model. The moment a covariate must be adjusted for, or you have several predictors, the two-group test cannot express it — move to regression/GLM, of which the test is a special case.

  • Reporting only significance. “p < 0.05” without an effect size hides whether the difference matters; a trivial effect can be significant in a huge sample and a large one non-significant in a tiny one.

From the sources

NoteWho says what
  • Martin & Bridgmon, Quantitative and Statistical Research Methods: From Hypothesis to Results — the pipeline framing (hypothesis and design determine the analysis); matching test to outcome type, number of groups, and level of measurement; and the discipline of specifying the analysis before the data.
  • Bruce, Bruce & Gedeck, Practical Statistics for Data Scientists — the unification of t-test / ANOVA / correlation as regression, choosing parametric vs resampling counterparts, and reporting effect sizes over bare significance.
  • Reinhart, Statistics Done Wrong — the false-positive cost of choosing tests after the fact, ignoring dependence (pseudoreplication), and multiplicity.

There is no such thing as *the* statistical test — there is the test that matches your **question**, your
**outcome variable**, the **structure** of your data, and the **design** that produced it. Get those four
right and the test almost picks itself; get any one wrong and a perfectly executed test answers the wrong
question. This page is the map. It routes you from a research question to a test, shows why most of those
tests are secretly the same model, and warns where the routing goes wrong.
:::

## Why it matters

Beginners memorise a menu of tests and then hunt for one that fits the data in front of them — often *after*
seeing the data, which is how false positives are manufactured. The professional move is the reverse: the
test is **implied** by the question and the design, decided before a single number is computed. Martin &
Bridgmon frame the whole enterprise as a pipeline "from hypothesis to results" — the hypothesis and the
design determine the analysis, not the other way round [@martin_bridgmon]. This entry makes that routing
explicit, and connects it to the deeper truth that nearly every classical test is a special case of
[regression](../03-regression/simple-linear-regression.qmd).

## Start with the question, not the test

Every analysis answers one of a small number of **question types**, and the type is the first fork in the road:

- **Difference** — do groups differ on some outcome? (treatment vs control, men vs women)
- **Association** — do two variables move together? (education and income)
- **Prediction** — can I forecast an outcome from inputs, and how well?
- **Change** — did something move over time or condition, *within the same units*? (before vs after)
- **Agreement** — do two measurements or raters concur? ([reliability](../00-overture/concepts-and-measurement.qmd))

Name the question type first. "I want a t-test" is putting the cart before the horse; "I want to know whether
two independent groups differ on a continuous outcome" *is* a two-sample t-test, stated as a question.

## The four things that pick the test

Once the question is named, four features of the data settle the test:

1. **Outcome (dependent) variable type** — is it **continuous** (a mean makes sense), **binary**, **nominal**
   (unordered categories), **ordinal** (ordered), a **count**, or a **time-to-event**? This is the single
   biggest determinant, and it is a question about the
   [level of measurement](../00-overture/concepts-and-measurement.qmd).
2. **Predictor / grouping structure** — how many groups (one, two, three or more), and is the predictor
   itself **categorical** or **continuous**? One continuous predictor points at correlation/regression; a
   grouping factor points at a group-comparison test.
3. **Dependence structure (the design)** — are observations **independent**, **paired/repeated** (the same
   units measured twice or more), or **clustered/nested** (students in classrooms)? This is set by the
   [study design](../00-overture/research-designs.qmd), and it changes the test even when everything else is
   identical.
4. **Assumptions** — does the outcome look roughly normal with comparable spread across groups, are cells
   large enough? When these hold, use the **parametric** test; when they fail, use its
   [nonparametric or resampling](resampling-and-nonparametric-tests.qmd) counterpart.

## Every test is a linear model

The reason all roads end in regression: the classical tests **are** regressions in disguise. A two-sample
t-test is a linear regression of the outcome on a single 0/1 group indicator — the slope is the mean
difference, and its $t$-statistic is *identical* to the t-test's. One-way ANOVA is regression on a set of
group dummies; a paired t-test is a regression with a per-subject intercept; Pearson correlation is the
slope of a standardised regression. [@bruce_practical] Seeing this collapses the menu into one idea and tells
you when to graduate: the moment you need to **adjust for a covariate**, the canned test has no slot for it,
but the regression does — add a term. Continuous outcome → [linear model](../03-regression/multiple-regression.qmd);
binary → [logistic](../03-regression/limited-dependent-variables.qmd); count → [Poisson](../03-regression/count-data-models.qmd);
time-to-event → [Cox](../03-regression/survival-analysis.qmd) — the [GLM](../03-regression/generalized-linear-models.qmd)
family is the test menu, unified.

```{python}
#| label: fig-test-is-model
#| fig-cap: "A two-sample t-test IS a regression on a group dummy. The same data, analysed both ways: on the left, two groups with a mean difference; the orange line is an OLS regression of the outcome on a 0/1 indicator, whose slope is exactly the difference in means. On the right, the two test statistics — the classical pooled two-sample t and the regression coefficient's t — are computed by hand and come out identical to the decimal. Same t, same degrees of freedom, therefore same p-value. The 'test' and the 'model' are one object; the model is just the version that lets you add covariates."
#| code-fold: true
#| code-summary: "Show the figure code"

import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
nA, nB = 30, 34
A = rng.normal(5.0, 1.6, nA)
B = rng.normal(6.1, 1.6, nB)

# --- classical pooled two-sample t-test, by hand ---
mA, mB = A.mean(), B.mean()
sp2 = ((nA-1)*A.var(ddof=1) + (nB-1)*B.var(ddof=1)) / (nA + nB - 2)
t_ttest = (mB - mA) / np.sqrt(sp2 * (1/nA + 1/nB))

# --- OLS of y on a 0/1 group dummy, by hand: t on the slope ---
y = np.concatenate([A, B])
x = np.concatenate([np.zeros(nA), np.ones(nB)])
X = np.column_stack([np.ones(len(y)), x])
beta = np.linalg.solve(X.T @ X, X.T @ y)          # [intercept, slope=mB-mA]
resid = y - X @ beta
s2 = resid @ resid / (len(y) - 2)
se_slope = np.sqrt(s2 * np.linalg.inv(X.T @ X)[1, 1])
t_reg = beta[1] / se_slope

fig, (axL, axR) = plt.subplots(1, 2, figsize=(8.6, 4.0),
                               gridspec_kw={"width_ratios": [1.25, 1]})
jit = rng.uniform(-0.06, 0.06, len(y))
axL.scatter(x + jit, y, s=16, color="#5e5e54", alpha=0.8, zorder=2)
xs = np.array([0, 1])
axL.plot(xs, beta[0] + beta[1]*xs, color="#e8531d", lw=2.6, zorder=3,
         label=f"OLS on dummy (slope = {beta[1]:.3f})")
axL.plot([0, 1], [mA, mB], "o", color="#161613", ms=9, zorder=4)
axL.set_xticks([0, 1]); axL.set_xticklabels(["group A", "group B"])
axL.set_ylabel("outcome  y"); axL.set_xlim(-0.35, 1.35)
axL.set_title("Regress y on a 0/1 group indicator", fontsize=10)
axL.legend(fontsize=8, frameon=False, loc="upper left")

axR.axis("off")
axR.text(0.5, 0.78, "same data, two ways", ha="center", fontsize=10, color="#161613", fontweight="bold")
axR.text(0.5, 0.55, f"two-sample t-test\n$t = {t_ttest:.4f}$", ha="center", fontsize=11, color="#5e5e54")
axR.text(0.5, 0.30, f"regression slope\n$t = {t_reg:.4f}$", ha="center", fontsize=11, color="#e8531d")
axR.text(0.5, 0.08, f"identical  (df = {nA+nB-2})", ha="center", fontsize=9.5,
         color="#161613", style="italic")
fig.tight_layout()
plt.show()

assert abs(t_ttest - t_reg) < 1e-10          # the point, guaranteed
```

## The design axis: dependence changes everything

Of the four features, **dependence structure** is the one beginners drop — and it is the most punishing. Two
datasets with identical outcomes and groups demand different tests if one is paired and the other independent,
or if observations cluster. Treating **clustered** data (pupils within schools, repeated measures within a
person, patients within a hospital) as if every observation were independent is **pseudoreplication**: you
claim far more independent information than you have, your standard errors shrink to a fiction, and your
false-positive rate explodes. The fix is a test that respects the design — aggregate to the cluster, or use a
[mixed-effects / fixed-effects model](../03-regression/mixed-effects-models.qmd). The simulation makes the
damage concrete.

```{python}
#| label: fig-clustering-error
#| fig-cap: "Ignoring the design inflates your false-positive rate. 2,000 simulated datasets under the null hypothesis of NO group difference, where observations are clustered (20 clusters, positively correlated within each) and the 'treatment' is assigned at the cluster level. The naive test treats all observations as independent; the correct test aggregates to cluster means first. Both should reject the true null about 5% of the time (dashed line). The naive test rejects far more often — it mistakes correlated repeats for independent evidence, manufacturing significance from nothing. Same data, same effect (zero); only the test's respect for the design differs."
#| code-fold: true
#| code-summary: "Show the figure code"

import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
n_sims = 2000
n_clusters = 20            # 10 per arm
per_cluster = 15
icc_sd = 1.0              # cluster-level random effect (creates within-cluster correlation)
noise_sd = 1.0

def one_sim():
    # cluster-level random intercepts; NO true treatment effect (null is true)
    clam = rng.normal(0, icc_sd, n_clusters)
    arm = np.array([0]*(n_clusters//2) + [1]*(n_clusters//2))
    y, g, cmeans_by_arm = [], [], {0: [], 1: []}
    for c in range(n_clusters):
        obs = clam[c] + rng.normal(0, noise_sd, per_cluster)   # no arm term added
        y.append(obs); g.append(np.full(per_cluster, arm[c]))
        cmeans_by_arm[arm[c]].append(obs.mean())
    y = np.concatenate(y); g = np.concatenate(g)

    # naive: pool all obs, two-sample t treating every obs as independent
    def t_stat(a, b):
        na, nb = len(a), len(b)
        sp2 = ((na-1)*a.var(ddof=1) + (nb-1)*b.var(ddof=1)) / (na+nb-2)
        return (b.mean() - a.mean()) / np.sqrt(sp2*(1/na + 1/nb))
    t_naive = t_stat(y[g == 0], y[g == 1])
    # correct: one number per cluster, then t on the 10 vs 10 cluster means
    t_correct = t_stat(np.array(cmeans_by_arm[0]), np.array(cmeans_by_arm[1]))
    return abs(t_naive), abs(t_correct)

res = np.array([one_sim() for _ in range(n_sims)])
crit = 1.96                                   # ~5% two-sided (normal approx)
err_naive = np.mean(res[:, 0] > crit) * 100
err_correct = np.mean(res[:, 1] > crit) * 100

fig, ax = plt.subplots(figsize=(7.2, 4.3))
bars = ax.bar(["naive\n(ignores clustering)", "correct\n(cluster means)"],
              [err_naive, err_correct], color=["#e8531d", "#161613"], width=0.55,
              edgecolor="#161613", linewidth=1.2, zorder=3)
ax.axhline(5, color="#5e5e54", lw=1.4, ls=(0, (4, 3)), zorder=2)
ax.text(1.45, 5, " 5% (correct rate)", color="#3a3a33", fontsize=9, va="bottom", ha="right")
for b, v in zip(bars, [err_naive, err_correct]):
    ax.text(b.get_x() + b.get_width()/2, v + 0.7, f"{v:.0f}%", ha="center",
            fontsize=11, fontweight="bold", color="#161613")
ax.set_ylabel("false-positive rate  (rejections of a true null)")
ax.set_ylim(0, max(err_naive, 10) * 1.2)
ax.set_title("Same null, same data — the naive test invents significance")
fig.tight_layout()
plt.show()
```

## Choose before you look; report the estimand

Two disciplines separate honest test choice from fishing:

- **Decide from the design, before the data.** The question and design fix the test in the analysis plan; a
  test chosen *after* inspecting the data (trying several, keeping the significant one) has an uncontrolled
  false-positive rate — the [garden of forking paths](replication-crisis.qmd) [@reinhart_swrong].
- **The test is not the goal; the estimate is.** A $p$-value answers "signal or noise?" but you almost always
  want the **magnitude** — report an [effect size and its confidence interval](effect-sizes.qmd), not just a
  verdict [@bruce_practical]. And size the study with [power](statistical-power.qmd) beforehand, correcting
  for [multiple comparisons](multiple-testing.qmd) if you run many.

## Common pitfalls

::: {.callout-warning title="Where test choice goes wrong"}

- **Picking the test after seeing the data.** Running a t-test, then a Mann–Whitney, then reporting whichever
  cleared 0.05, is p-hacking. Choose from the design in advance. [@reinhart_swrong]

- **Ignoring dependence.** Paired data run as independent (or clustered data pooled as independent) uses the
  wrong standard error — the simulation above shows false positives exploding. Match the test to the design.

- **Forcing a mean onto the wrong scale.** A t-test on an **ordinal** 1–5 rating, or on a heavily skewed
  outcome, can mislead; use a rank-based or [nonparametric](resampling-and-nonparametric-tests.qmd) test, or
  model the scale properly. Levels of measurement constrain what is meaningful. [@martin_bridgmon]

- **Reaching for a canned test when you need a model.** The moment a covariate must be adjusted for, or you
  have several predictors, the two-group test cannot express it — move to
  [regression/GLM](../03-regression/generalized-linear-models.qmd), of which the test is a special case.

- **Reporting only significance.** "p < 0.05" without an [effect size](effect-sizes.qmd) hides whether the
  difference matters; a trivial effect can be significant in a huge sample and a large one non-significant in
  a tiny one.

:::
