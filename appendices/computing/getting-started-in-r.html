Getting Started in R

  • Show All Code
  • Hide All Code
  • View Source

The small part of R you need first: how to store numbers, hold a dataset, chain steps together and package up anything you repeat.

You do not need to learn all of R before it becomes useful. Four habits carry most applied work: do arithmetic on whole columns of numbers at once, keep each dataset in one table, write a sequence of steps so it reads top to bottom, and turn any block you keep copying into a reusable command. This page is the on-ramp to the language itself.

TipWhere you probably came from — and what you need

You likely arrived from the Thinking in Dataframes track, whose snippets assume you can read basic R, from exploratory data analysis, or from the computing appendix on your way to reading a regression in R. The question you came with is probably “what do <-, c() and |> actually mean?”

You need: nothing beyond school arithmetic. You don’t need to have programmed before, or to know the tidyverse. That comes next, in the dataframes track.

Jump to what you came for: the idea in words · a first session, line by line · vectors · data frames · the pipe and functions · compute, then look

Why it matters

The source library behind this encyclopedia is mostly written in R, and so is much of applied social science. The dataframe track, the regression appendix and most textbook code examples assume you can read a few lines of it. People learning R often get stuck on its basic way of working (whole-vector arithmetic, missing values, categories stored as factors) rather than on any statistics. A small amount of the right knowledge removes most of that friction (Dayal 2015; Wickham et al. 2023).

The idea in words

Think of R as a calculator with a memory and a vocabulary.

  • The memory is a set of named boxes called objects. You put something in a box with <-, read as “gets”: price <- 10 means “the box called price gets 10”. The name is case-sensitive, so Price and price are different boxes (Dayal 2015).
  • The vocabulary is a set of functions: commands that take inputs in round brackets and give back a result, like sum(price) or mean(age). An input to a function is called an argument.
  • The working unit is a list of values, not one value. A vector is an ordered set of values of one type, made with c() (“combine”). Arithmetic on a vector applies to every element at once, so you rarely need to loop.
  • A dataset is a table of vectors. A data frame is several vectors of the same length side by side, one per variable, with one row per observation.

Everything below builds those four ideas up, one at a time.

A first session, line by line

This is the first example in Dayal’s Introduction to R for Quantitative Economics (Dayal 2015): three goods, their prices, the quantities bought, and the total spent. Lines starting with #> show what R prints.

Price    <- c(10, 3, 15)
Quantity <- c(25, 3, 20)
Expenditure <- Price * Quantity
Expenditure
#> [1] 250   9 300
sum(Expenditure)
#> [1] 559

Reading it line by line:

  1. Price <- c(10, 3, 15) makes a vector of three prices and stores it under the name Price. Nothing is printed. R just remembers it.
  2. Quantity <- c(25, 3, 20) does the same for quantities.
  3. Price * Quantity multiplies element by element: 10\times25, 3\times3, 15\times20. There is no loop. That is what vectorised means.
  4. Typing a name on its own prints it. The [1] is not part of the data. It tells you the line starts with element number 1.
  5. sum() is a function that takes the whole vector and returns one number, the total: 559.

Two follow-ups from the same chapter show what goes wrong. Typing price (lower case) gives Error: object 'price' not found. Adding vectors of different lengths makes R recycle the shorter one: c(3, 3, 3) + c(2, 9) gives 5 12 5, with a warning, because R went back to the start of the shorter vector for the third element (Dayal 2015).

NoteJargon key — open if a term is unfamiliar
  • Object — anything stored under a name: a number, a vector, a data frame, a fitted model.
  • <- — assignment: put the value on the right into the name on the left.
  • Function — a named command, used as name(arguments); it takes inputs and returns a result.
  • Argument — an input to a function. Arguments can be named, as in mean(x, na.rm = TRUE).
  • Vector — an ordered set of values of one type, made with c().
  • Vectorised — applied to every element of a vector at once.
  • Data frame / tibble — a table: named columns (vectors) of equal length. A tibble is the tidyverse’s version.
  • Factor — a categorical variable with a fixed set of levels.
  • NA — R’s code for a missing value (“not available”).
  • Pipe (|>) — passes the result on its left into the function on its right.
  • Package — an add-on bundle of functions, installed once and loaded with library().

R thinks in vectors

The single most important habit: R operates on whole vectors at once, not element by element. A vector is made with c(), and arithmetic is vectorised — it applies to every element without a loop. (Kaplan 2024)

x <- c(4, 8, 15, 16, 23, 42)   # a numeric vector;  <- is assignment
x * 2                          # 8 16 30 32 46 84   — no loop needed
mean(x); sd(x); length(x)      # 18, 13.49, 6 — summaries take the whole vector
x[x > 15]                      # 16 23 42            — logical subsetting

The last line is worth reading slowly. x > 15 produces a vector of TRUE/FALSE values, one per element. Putting it inside square brackets keeps only the elements where it is TRUE. Square brackets pick elements and round brackets call functions; mixing them up is a common early error (Dayal 2015).

Writing a for loop where a vectorised expression would do is the most common beginner’s tell; R is faster and clearer when you let the vector operation speak. The main atomic types are numeric, character ("text"), logical (TRUE/FALSE), and factor (categorical — a character with a fixed set of levels, which is how R encodes groups for models). (McNulty 2021)

Keep your data in a data frame

A data frame (or its modern form, the tibble) is R’s table: named columns that can hold different types, all the same length — one row per observation, one column per variable. It is the object every modelling and plotting verb expects. (Dayal 2020)

d <- data.frame(
  name = c("Ann", "Ben", "Cy"),
  age  = c(31, 25, 40),
  group = factor(c("T", "C", "T"))
)
d$age            # a column, by name ($)
d[d$group == "T", ]   # rows where group is T, all columns
nrow(d); names(d)     # dimensions and column names

In plain words: d$age pulls out one column as a vector. Inside d[rows, columns], the part before the comma picks rows and the part after picks columns. Leaving the column part blank means “all columns”. Dayal builds his first data frame the same way, from the Price and Quantity vectors: data.frame(Price, Quantity) (Dayal 2015).

Load real data with the readr package (read_csv("file.csv")); everything downstream assumes it arrived as a tidy data frame. (Llaudet and Imai 2022)

The pipe, and writing functions

The pipe |> passes the thing on its left as the first argument of the function on its right, so a sequence of steps reads top-to-bottom instead of inside-out: (Kaplan 2024)

# nested (hard to read)           # piped (reads as steps)
round(mean(x, na.rm = TRUE), 2)   x |> mean(na.rm = TRUE) |> round(2)

R for Data Science suggests reading the pipe aloud as “then”: take x, then take the mean, then round it (Wickham et al. 2023). (That book’s first edition writes the pipe as %>%, from the magrittr package; |> is the version built into R. For simple chains like this one they behave the same.)

And when you find yourself copying a block of code with one thing changed, make it a function:

z_score <- function(v) {          # v is the argument
  (v - mean(v)) / sd(v)           # last expression is returned
}
z_score(x)                        # -1.04 -0.74 -0.22 -0.15 0.37 1.78 (rounded)

Wickham’s rule of thumb is to write a function once you have copied and pasted a block more than twice. His example is a copied rescaling line in which one a was never changed to b, a silent bug that a function would have prevented (Wickham et al. 2023). A function has three parts: a name (z_score), its arguments inside function(), and a body in curly braces. The value of the last line of the body is what the function returns (Wickham et al. 2023).

Functions plus vectorisation are the whole game: express the operation once, apply it to any vector.

Compute, then look — always

The reason social scientists learn to simulate and plot, not just compute summaries, is that summaries hide shape. Anscombe’s quartet is the classic demonstration, and it is a one-line lesson worth internalising before any modelling. (Dayal 2015)

Show the figure code 
import numpy as np
import matplotlib.pyplot as plt

x123 = np.array([10, 8, 13, 9, 11, 14, 6, 4, 12, 7, 5])
data = {
    "I":   (x123, np.array([8.04,6.95,7.58,8.81,8.33,9.96,7.24,4.26,10.84,4.82,5.68])),
    "II":  (x123, np.array([9.14,8.14,8.74,8.77,9.26,8.10,6.13,3.10,9.13,7.26,4.74])),
    "III": (x123, np.array([7.46,6.77,12.74,7.11,7.81,8.84,6.08,5.39,8.15,6.42,5.73])),
    "IV":  (np.array([8,8,8,8,8,8,8,19,8,8,8]),
            np.array([6.58,5.76,7.71,8.84,8.47,7.04,5.25,12.50,5.56,7.91,6.89])),
}
xs = np.linspace(3, 20, 50)

fig, axes = plt.subplots(2, 2, figsize=(7.8, 5.4), sharex=True, sharey=True)
for ax, (name, (x, y)) in zip(axes.flat, data.items()):
    b1 = np.cov(x, y, bias=True)[0, 1] / np.var(x)     # slope, by hand
    b0 = y.mean() - b1 * x.mean()
    r = np.corrcoef(x, y)[0, 1]
    ax.plot(xs, b0 + b1 * xs, color="#e8531d", lw=2.0, zorder=1)
    ax.scatter(x, y, s=28, color="#161613", zorder=2, edgecolor="#f4f3ec", linewidth=0.6)
    ax.set_title(f"Set {name}:  r = {r:.2f},  ŷ = {b0:.1f} + {b1:.2f}x", fontsize=9)
    ax.set_xlim(2, 20); ax.set_ylim(2, 14)
fig.suptitle("Same statistics, four different realities — so plot the data", fontsize=11)
fig.tight_layout()
plt.show()

Common pitfalls

WarningWhere new R users trip

  • Looping instead of vectorising. for (i in 1:length(x)) x[i] <- x[i]*2 is slow and un-R; write x * 2. Reach for a loop only when each step truly depends on the last. (Kaplan 2024)

  • Confusing <-, =, and ==. <- assigns, == tests equality, and a single = assigns inside a function call (an argument). Mixing them up produces silent surprises, not errors.

  • NA propagates. Missing values are “contagious”: almost any operation involving an unknown value gives an unknown result (Wickham et al. 2023). mean(x) on a vector with one NA is NA — you must ask for mean(x, na.rm = TRUE). R makes you acknowledge missingness on purpose.

  • Recycling. Operating on vectors of different lengths silently recycles the shorter one. c(1,2,3,4) + c(0,10) gives 1 12 3 14, not an error — occasionally handy, often a bug. R warns only when the longer length is not a multiple of the shorter, as in Dayal’s 5 12 5 example. (Dayal 2015)

  • Case and bracket slips. Price and price are different objects, and c[10, 3, 15] (square brackets) is an error where c(10, 3, 15) was meant. (Dayal 2015)

  • Factor surprises. A grouping variable read as text may need factor(); and a factor’s reference level (the one folded into the intercept) is the first alphabetically unless you set it — the source of “why is my category missing from the regression?” (McNulty 2021)

This is the first example in Dayal's *Introduction to R for Quantitative Economics* [@dayal_r_econ]: three
goods, their prices, the quantities bought, and the total spent. Lines starting with `#>` show what R prints.

```r
Price    <- c(10, 3, 15)
Quantity <- c(25, 3, 20)
Expenditure <- Price * Quantity
Expenditure
#> [1] 250   9 300
sum(Expenditure)
#> [1] 559
```

Reading it line by line:

1. `Price <- c(10, 3, 15)` makes a vector of three prices and stores it under the name `Price`. Nothing is
   printed. R just remembers it.
2. `Quantity <- c(25, 3, 20)` does the same for quantities.
3. `Price * Quantity` multiplies **element by element**: $10\times25$, $3\times3$, $15\times20$. There is no
   loop. That is what *vectorised* means.
4. Typing a name on its own prints it. The `[1]` is not part of the data. It tells you the line starts with
   element number 1.
5. `sum()` is a function that takes the whole vector and returns one number, the total: 559.

Two follow-ups from the same chapter show what goes wrong. Typing `price` (lower case) gives
`Error: object 'price' not found`. Adding vectors of different lengths makes R **recycle** the shorter one:
`c(3, 3, 3) + c(2, 9)` gives `5 12 5`, with a warning, because R went back to the start of the shorter vector
for the third element [@dayal_r_econ].

::: {.callout-note collapse="true" title="Jargon key — open if a term is unfamiliar"}
- **Object** — anything stored under a name: a number, a vector, a data frame, a fitted model.
- **`<-`** — assignment: put the value on the right into the name on the left.
- **Function** — a named command, used as `name(arguments)`; it takes inputs and returns a result.
- **Argument** — an input to a function. Arguments can be named, as in `mean(x, na.rm = TRUE)`.
- **Vector** — an ordered set of values of one type, made with `c()`.
- **Vectorised** — applied to every element of a vector at once.
- **Data frame / tibble** — a table: named columns (vectors) of equal length. A tibble is the tidyverse's
  version.
- **Factor** — a categorical variable with a fixed set of *levels*.
- **`NA`** — R's code for a missing value ("not available").
- **Pipe (`|>`)** — passes the result on its left into the function on its right.
- **Package** — an add-on bundle of functions, installed once and loaded with `library()`.
:::

## R thinks in vectors {#sec-vectors}

The single most important habit: R operates on **whole vectors at once**, not element by element. A vector is
made with `c()`, and arithmetic is *vectorised* — it applies to every element without a loop. [@kaplan_lessons]

```r
x <- c(4, 8, 15, 16, 23, 42)   # a numeric vector;  <- is assignment
x * 2                          # 8 16 30 32 46 84   — no loop needed
mean(x); sd(x); length(x)      # 18, 13.49, 6 — summaries take the whole vector
x[x > 15]                      # 16 23 42            — logical subsetting
```

The last line is worth reading slowly. `x > 15` produces a vector of `TRUE`/`FALSE` values, one per element.
Putting it inside square brackets keeps only the elements where it is `TRUE`. Square brackets pick elements and
round brackets call functions; mixing them up is a common early error [@dayal_r_econ].

Writing a `for` loop where a vectorised expression would do is the most common beginner's tell; R is faster and
clearer when you let the vector operation speak. The main atomic types are **numeric**, **character**
(`"text"`), **logical** (`TRUE`/`FALSE`), and **factor** (categorical — a character with a fixed set of
*levels*, which is how R encodes groups for models). [@mcnulty_rmodeling]

## Keep your data in a data frame {#sec-dataframes}

A **data frame** (or its modern form, the **tibble**) is R's table: named columns that can hold different
types, all the same length — one row per observation, one column per variable. It is the object every
modelling and plotting verb expects. [@dayal_r_datascience]

```r
d <- data.frame(
  name = c("Ann", "Ben", "Cy"),
  age  = c(31, 25, 40),
  group = factor(c("T", "C", "T"))
)
d$age            # a column, by name ($)
d[d$group == "T", ]   # rows where group is T, all columns
nrow(d); names(d)     # dimensions and column names
```

In plain words: `d$age` pulls out one column as a vector. Inside `d[rows, columns]`, the part before the comma
picks rows and the part after picks columns. Leaving the column part blank means "all columns". Dayal builds
his first data frame the same way, from the `Price` and `Quantity` vectors: `data.frame(Price, Quantity)`
[@dayal_r_econ].

Load real data with the **readr** package (`read_csv("file.csv")`); everything downstream assumes it arrived as
a tidy data frame. [@llaudet_imai_dss]

## The pipe, and writing functions {#sec-pipe}

The **pipe** `|>` passes the thing on its left as the first argument of the function on its right, so a
sequence of steps reads top-to-bottom instead of inside-out: [@kaplan_lessons]

```r
# nested (hard to read)           # piped (reads as steps)
round(mean(x, na.rm = TRUE), 2)   x |> mean(na.rm = TRUE) |> round(2)
```

*R for Data Science* suggests reading the pipe aloud as "then": take `x`, *then* take the mean, *then* round
it [@wickham_r4ds]. (That book's first edition writes the pipe as `%>%`, from the magrittr package; `|>` is
the version built into R. For simple chains like this one they behave the same.)

And when you find yourself copying a block of code with one thing changed, make it a **function**:

```r
z_score <- function(v) {          # v is the argument
  (v - mean(v)) / sd(v)           # last expression is returned
}
z_score(x)                        # -1.04 -0.74 -0.22 -0.15 0.37 1.78 (rounded)
```

Wickham's rule of thumb is to write a function once you have copied and pasted a block more than twice. His
example is a copied rescaling line in which one `a` was never changed to `b`, a silent bug that a function would
have prevented [@wickham_r4ds]. A function has three parts: a **name** (`z_score`), its **arguments** inside
`function()`, and a **body** in curly braces. The value of the last line of the body is what the function
returns [@wickham_r4ds].

Functions plus vectorisation are the whole game: express the operation once, apply it to any vector.

## Compute, then look — always {#sec-look}

The reason social scientists learn to *simulate and plot*, not just compute summaries, is that summaries hide
shape. Anscombe's quartet is the classic demonstration, and it is a one-line lesson worth internalising before
any modelling. [@dayal_r_econ]

```{python}
#| label: fig-anscombe
#| fig-cap: "Anscombe's quartet: four datasets with near-identical summary statistics — same mean of x and y, same variance, same correlation (r ≈ 0.82), and the same fitted line ŷ = 3 + 0.5x (orange) — yet four completely different stories. Only the scatter reveals the curve, the outlier, and the leverage point. This is why every figure in this encyclopedia is a plot, not a table of moments: the number can be identical while the reality is not. Compute, then look."
#| code-fold: true
#| code-summary: "Show the figure code"

import numpy as np
import matplotlib.pyplot as plt

x123 = np.array([10, 8, 13, 9, 11, 14, 6, 4, 12, 7, 5])
data = {
    "I":   (x123, np.array([8.04,6.95,7.58,8.81,8.33,9.96,7.24,4.26,10.84,4.82,5.68])),
    "II":  (x123, np.array([9.14,8.14,8.74,8.77,9.26,8.10,6.13,3.10,9.13,7.26,4.74])),
    "III": (x123, np.array([7.46,6.77,12.74,7.11,7.81,8.84,6.08,5.39,8.15,6.42,5.73])),
    "IV":  (np.array([8,8,8,8,8,8,8,19,8,8,8]),
            np.array([6.58,5.76,7.71,8.84,8.47,7.04,5.25,12.50,5.56,7.91,6.89])),
}
xs = np.linspace(3, 20, 50)

fig, axes = plt.subplots(2, 2, figsize=(7.8, 5.4), sharex=True, sharey=True)
for ax, (name, (x, y)) in zip(axes.flat, data.items()):
    b1 = np.cov(x, y, bias=True)[0, 1] / np.var(x)     # slope, by hand
    b0 = y.mean() - b1 * x.mean()
    r = np.corrcoef(x, y)[0, 1]
    ax.plot(xs, b0 + b1 * xs, color="#e8531d", lw=2.0, zorder=1)
    ax.scatter(x, y, s=28, color="#161613", zorder=2, edgecolor="#f4f3ec", linewidth=0.6)
    ax.set_title(f"Set {name}:  r = {r:.2f},  ŷ = {b0:.1f} + {b1:.2f}x", fontsize=9)
    ax.set_xlim(2, 20); ax.set_ylim(2, 14)
fig.suptitle("Same statistics, four different realities — so plot the data", fontsize=11)
fig.tight_layout()
plt.show()
```

## Common pitfalls

::: {.callout-warning title="Where new R users trip"}

- **Looping instead of vectorising.** `for (i in 1:length(x)) x[i] <- x[i]*2` is slow and un-R; write `x * 2`.
  Reach for a loop only when each step truly depends on the last. [@kaplan_lessons]

- **Confusing `<-`, `=`, and `==`.** `<-` assigns, `==` tests equality, and a single `=` assigns *inside a
  function call* (an argument). Mixing them up produces silent surprises, not errors.

- **`NA` propagates.** Missing values are "contagious": almost any operation involving an unknown value gives
  an unknown result [@wickham_r4ds]. `mean(x)` on a vector with one `NA` is `NA` — you must ask for
  `mean(x, na.rm = TRUE)`. R makes you acknowledge missingness on purpose.

- **Recycling.** Operating on vectors of different lengths silently *recycles* the shorter one. `c(1,2,3,4) +
  c(0,10)` gives `1 12 3 14`, not an error — occasionally handy, often a bug. R warns only when the longer
  length is not a multiple of the shorter, as in Dayal's `5 12 5` example. [@dayal_r_econ]

- **Case and bracket slips.** `Price` and `price` are different objects, and `c[10, 3, 15]` (square brackets)
  is an error where `c(10, 3, 15)` was meant. [@dayal_r_econ]

- **Factor surprises.** A grouping variable read as text may need `factor()`; and a factor's *reference level*
  (the one folded into the intercept) is the first alphabetically unless you set it — the source of "why is my
  category missing from the regression?" [@mcnulty_rmodeling]

:::
