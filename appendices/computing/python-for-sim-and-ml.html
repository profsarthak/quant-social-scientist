Python for Simulation & ML

  • Show All Code
  • Hide All Code
  • View Source

The small set of Python tools behind every figure on this site: one for doing arithmetic on whole lists of numbers, one for drawing random numbers, one for plotting, and one for fitting machine-learning models.

Python earns its place here for two jobs. The first is simulation: make up random data thousands of times and watch what a statistic does. The second is machine learning: fit a prediction model and check it on data it has not seen. Every figure in this encyclopedia is drawn by hand with two Python packages, so the code under each figure shows the whole computation. This page is the key to reading that code.

TipWhere you probably came from — and what you need

You likely arrived from simulation & Monte Carlo or the bootstrap, wanting to run the idea yourself; from the “Show the figure code” fold under any figure on the site; or from the ML track. The question you came with is probably “what do rng, np. and @ mean in this code?”

You need: to recognise a variable and a function call (name = value, f(x)). If you have read getting started in R, most ideas carry straight over: a numpy array behaves much like an R vector. You don’t need to have written Python, or to know pandas or object-oriented programming.

Why it matters

Many of the ideas in this encyclopedia are easiest to understand by simulating them. The bootstrap, a permutation test, the Central Limit Theorem and the power of a study all come down to “generate data, compute a statistic, repeat, look at the spread”. Bruce & Bruce present the bootstrap as exactly such a recipe (Bruce et al. 2020). Reinhart suggests the same check for power: simulate many artificial datasets with the effect size you expect and count how often the test detects it (Reinhart 2015). A few lines of Python carry out any of these recipes, and once you can read those lines you can change the inputs and rerun the experiment.

The idea in words

Four tools, four jobs.

  • numpy stores numbers as an array: a block of values of one type, like an R vector or a column of a spreadsheet. Arithmetic on an array applies to every element at once, with no loop.
  • A random-number generator (rng) is a machine that produces random draws. You start it from a seed, a number that fixes which stream of random numbers you get, so the same seed always gives the same draws.
  • matplotlib draws figures. A figure is the canvas; an axes is one panel on it; you add marks (lines, points, bars) to the axes one at a time.
  • scikit-learn fits machine-learning models. Every model is used the same way: create it, fit it on training data, predict on new data.

Python code often reads as thing.action(). The dot means “the action that belongs to this thing”, so x.mean() is the mean of x and rng.normal(...) asks the generator rng for normal draws. A function attached to an object like this is called a method.

A bootstrap, line by line

Bruce & Bruce describe the bootstrap for a sample mean as an algorithm: draw a value from the sample, record it and put it back; repeat until you have as many values as the sample; record their mean; do all of that many times; then use the spread of the recorded means as the standard error (Bruce et al. 2020). Here it is in numpy, on a six-number sample. Lines starting with #> show the output.

import numpy as np
x = np.array([4, 8, 15, 16, 23, 42])
rng = np.random.default_rng(42)
rng.choice(x, size=6, replace=True)
#> array([ 4, 23, 16, 15, 15, 42])
means = np.array([rng.choice(x, size=6, replace=True).mean() for _ in range(1000)])
means.std(ddof=1)
#> 4.902136...
np.percentile(means, [2.5, 97.5])
#> array([ 9.4958, 28.6667])

Reading it line by line:

  1. import numpy as np loads numpy and lets you call it np for short.
  2. np.array([...]) turns a Python list into an array: the sample of six numbers, with mean 18.
  3. np.random.default_rng(42) creates a random-number generator from seed 42. Anyone who runs this gets the same draws.
  4. rng.choice(x, size=6, replace=True) draws six values from x with replacement, so a value can come up twice (15 does here) and another not at all (8). This is one bootstrap resample.
  5. The next line does that 1,000 times. for _ in range(1000) means “repeat 1,000 times” (the _ is a name for a counter you don’t use). Each time it takes the .mean() of the resample, and np.array(...) collects the 1,000 means.
  6. means.std(ddof=1) is their standard deviation, about 4.9: the bootstrap standard error of the mean. The textbook formula s/\sqrt{n} gives 5.5. With only six numbers the two are close but not equal; the bootstrap needs no formula at all.
  7. np.percentile(means, [2.5, 97.5]) finds the values that cut off the lowest and highest 2.5% of the 1,000 means. The middle 95% runs from about 9.5 to 28.7: a bootstrap confidence interval.

The ddof=1 matters. numpy’s .std() divides by n unless told otherwise, so x.std() gives 12.32, while R’s sd(x) and x.std(ddof=1) divide by n-1 and give 13.49. ddof stands for “delta degrees of freedom”, the number subtracted from n.

NoteJargon key — open if a term is unfamiliar
  • Package / module — a bundle of code you load with import; np and plt are the usual short names for numpy and matplotlib’s plotting module.
  • Array (ndarray) — numpy’s block of numbers of one type; one-dimensional like a vector, or two-dimensional like a matrix.
  • Shape — an array’s size along each dimension: (6,) for six numbers in a row, (3, 2) for 3 rows and 2 columns.
  • Axis — one of those dimensions; axis=0 runs down the rows (so mean(axis=0) averages each column).
  • Vectorised — applied to every element at once, in fast compiled code, with no Python loop.
  • Broadcasting — numpy’s rule for combining arrays of different but compatible shapes by stretching the smaller one.
  • Method — a function attached to an object, called with a dot: x.mean().
  • Generator and seed — the random-number machine (rng) and the number that fixes its stream.
  • With replacement — each drawn value is put back before the next draw, so it can be drawn again.
  • View vs copy — a view is a window onto an existing array (changing it changes the original); a copy is independent.
  • Estimator — in scikit-learn, a model object with fit and predict methods.

numpy: think in arrays

numpy’s ndarray is Python’s answer to R’s vector: a homogeneous block of numbers that operations run over all at once, in fast compiled code, with no Python loop. It is the same habit as thinking in vectors in R.

import numpy as np

x = np.array([4, 8, 15, 16, 23, 42])
x * 2                    # array([ 8, 16, 30, 32, 46, 84]) — vectorised
x[x > 15]                # array([16, 23, 42])            — boolean mask
x.mean(), x.std()        # reductions over the whole array (18.0 and 12.32: std divides by n)
M = np.ones((3, 2))      # a 3x2 matrix of ones
M @ M.T                  # matrix multiply (the @ operator)

In plain words: x > 15 makes a list of True/False values, one per element, and x[...] keeps the True ones. M.T is M turned on its side (its transpose), and @ multiplies matrices.

Broadcasting is the one idea to internalise: numpy stretches mismatched-but-compatible shapes so data - data.mean(axis=0) centres every column without a loop. It is the source of numpy’s speed and, occasionally, of silent bugs (below).

Randomness and simulation

Simulation is numpy’s quiet superpower. The modern interface is a generator seeded for reproducibility:

rng = np.random.default_rng(42)     # seeded generator
rng.normal(0, 1, size=1000)         # draws from N(0,1)
rng.integers(0, 6, size=10)         # dice
rng.choice(data, size=100, replace=True)   # a bootstrap resample

Draw, compute a statistic, repeat — that loop is the bootstrap, a permutation test, and every Monte-Carlo argument in the book. In the bootstrap the resampling is always with replacement; in a permutation test the data are reshuffled without it (Bruce et al. 2020). The figure below is the canonical example.

Linear algebra, done right

np.linalg is where the matrix formulas become code — and it is why those entries solve rather than invert:

beta = np.linalg.solve(X.T @ X, X.T @ y)   # normal equations — do this
beta = np.linalg.inv(X.T @ X) @ X.T @ y    # mathematically equal, numerically worse

In plain words: both lines compute the least-squares coefficients \hat\beta = (X^\top X)^{-1}X^\top y. The first asks numpy to solve the equations X^\top X\,\beta = X^\top y directly; the second first builds the inverse matrix and then multiplies, which is slower and loses more precision to rounding.

solve (and lstsq, or a QR/SVD) is faster and more stable than forming an explicit inverse — the practical lesson from OLS in matrix form, in one line. The coefficient plot in the R regression appendix computes its estimates exactly this way.

matplotlib is the figure engine

Every plot in this encyclopedia is matplotlib, written by hand: a figure, one or more axes, and explicit marks. No seaborn, no ggplot-style grammar — just the primitives, so the code says exactly what the picture means. That is a deliberate house choice, not a limitation.

The pattern under every figure is the same three steps: fig, ax = plt.subplots() makes the canvas and a panel; calls like ax.plot(...), ax.scatter(...) and ax.axhline(...) add marks; ax.set_xlabel(...) and ax.set_title(...) label it. Reading those calls top to bottom tells you everything the figure shows.

Where scikit-learn fits

For applied machine learning — the ML track put to work — scikit-learn gives every model the same three-verb interface, which is most of what makes Python pleasant for ML. The models themselves (the lasso, trees, boosting) are what Murphy and ISLR explain (Murphy 2012; James et al. 2021).

from sklearn.linear_model import Lasso
from sklearn.model_selection import train_test_split

Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0)
model = Lasso(alpha=0.1).fit(Xtr, ytr)     # fit
pred  = model.predict(Xte)                  # predict
model.score(Xte, yte)                       # evaluate

In plain words: hold back 30% of the rows as a test set; fit a lasso on the other 70%; predict the held-back rows; score how well the predictions match. The test rows play no part in the fit, which is the point: ISLR’s validation-set approach estimates test error on observations the model never saw (James et al. 2021).

fit / predict / score is the same for a random forest, a gradient booster, or a logistic regression — you swap the estimator and the workflow is unchanged. The concepts behind them live in the ML track; this is the tooling that runs them.

Show the figure code 
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
N = 4000
pts = rng.random((N, 2))                       # N points in the unit square
inside = (pts[:, 0]**2 + pts[:, 1]**2) <= 1.0  # inside the quarter circle?
pi_running = 4.0 * np.cumsum(inside) / np.arange(1, N + 1)

fig, (axL, axR) = plt.subplots(1, 2, figsize=(8.6, 4.2),
                               gridspec_kw={"width_ratios": [1, 1.15]})

# Left: the drops
axL.scatter(pts[inside, 0], pts[inside, 1], s=5, color="#e8531d", alpha=0.7, label="inside")
axL.scatter(pts[~inside, 0], pts[~inside, 1], s=5, color="#b7b6a8", alpha=0.7, label="outside")
theta = np.linspace(0, np.pi / 2, 100)
axL.plot(np.cos(theta), np.sin(theta), color="#161613", lw=2.0)
axL.set_aspect("equal"); axL.set_xlim(0, 1); axL.set_ylim(0, 1)
axL.set_title(f"{N} random points  →  π ≈ {pi_running[-1]:.3f}", fontsize=10)
axL.legend(fontsize=8, frameon=False, loc="upper right")
axL.grid(False)

# Right: convergence
axR.plot(np.arange(1, N + 1), pi_running, color="#e8531d", lw=1.6)
axR.axhline(np.pi, color="#161613", lw=1.2, ls=(0, (4, 3)))
axR.text(N, np.pi + 0.04, " π", color="#161613", fontsize=10, va="bottom", ha="right")
axR.set_xscale("log")
axR.set_ylim(2.6, 3.7)
axR.set_xlabel("number of draws (log scale)"); axR.set_ylabel("running estimate of π")
axR.set_title("The estimate converges (LLN)", fontsize=10)

fig.suptitle("Monte-Carlo π: random points and counting, nothing else", fontsize=11)
fig.tight_layout()
plt.show()

Reading the figure code with the jargon key: rng.random((N, 2)) is an array of shape (4000, 2), one row per point; inside is a True/False array; np.cumsum(inside) is the running count of hits, so dividing by 1, 2, …, N gives the running fraction. Everything is vectorised; there is no loop over points.

Common pitfalls

WarningWhere the Python stack bites

  • Float equality. 0.1 + 0.2 == 0.3 is False (the sum is stored as 0.30000000000000004). Compare with np.isclose(a, b), never ==, for floating-point results.

  • The std default. x.std() divides by n, not n-1: 12.32 rather than R’s 13.49 for the six-number example. Pass ddof=1 when you want the sample standard deviation.

  • Broadcasting surprises. A (n,) vector and an (n,1) column broadcast to an (n,n) matrix — rarely what you meant. Check .shape when an operation returns something suspiciously large.

  • Views vs copies. Slicing an array returns a view; writing to it mutates the original. Use .copy() when you need independence, or track down a “why did my data change?” bug.

  • Leakage in scikit-learn. Fit scalers/imputers on the training split only, then apply to test — do it on the full data and your cross-validation score is optimistic. Use a Pipeline so the preprocessing is refit inside each fold. This is ISLR’s rule that test observations play no part in fitting (James et al. 2021), applied to preprocessing as well as to the model.

  • Reaching for heavy libraries reflexively. A histogram, a bootstrap, a projection — these are a few lines of numpy. Pulling in seaborn/pandas/sklearn for a one-liner adds dependencies and hides the mechanism the figure is meant to show.

From the sources

NoteWho says what
  • Bruce & Bruce, Practical Statistics for Data Scientists — the bootstrap as an explicit resampling algorithm (draw with replacement, record the statistic, repeat, use the spread), and the bootstrap-vs-permutation distinction. The corpus copy is the 2017 first edition, whose code is in R; the Python translation here is this encyclopedia’s.
  • Reinhart, Statistics Done Wrong — estimating power by simulating many artificial datasets.
  • Murphy, Machine Learning: A Probabilistic Perspective, and James et al., ISLR — the models behind scikit-learn’s estimators and the train/test discipline (the validation-set approach).
  • What the corpus does not cover: none of the source texts teaches numpy, matplotlib or scikit-learn as software. Function names and behaviour on this page (default_rng, ddof, broadcasting, views, fit/predict/score) are standard library behaviour, checked by running the code, and are not attributed to any source. An earlier version of this page credited the numpy idiom to Bruce & Bruce and the leakage caution to ISLR; both credits were broader than the texts support.
  • This repository — every figure is hand-built numpy + matplotlib; the Monte-Carlo π above is the template for “simulate, then plot.”

## Why it matters

Many of the ideas in this encyclopedia are easiest to understand by simulating them. The bootstrap, a
permutation test, the Central Limit Theorem and the power of a study all come down to "generate data, compute
a statistic, repeat, look at the spread". Bruce & Bruce present the bootstrap as exactly such a recipe
[@bruce_practical]. Reinhart suggests the same check for power: simulate many artificial datasets with the
effect size you expect and count how often the test detects it [@reinhart_swrong]. A few lines of Python
carry out any of these recipes, and once you can read those lines you can change the inputs and rerun the
experiment.

## The idea in words {#sec-idea}

Four tools, four jobs.

- **numpy** stores numbers as an **array**: a block of values of one type, like an R vector or a column of a
  spreadsheet. Arithmetic on an array applies to every element at once, with no loop.
- **A random-number generator** (`rng`) is a machine that produces random draws. You start it from a
  **seed**, a number that fixes which stream of random numbers you get, so the same seed always gives the same
  draws.
- **matplotlib** draws figures. A *figure* is the canvas; an *axes* is one panel on it; you add marks (lines,
  points, bars) to the axes one at a time.
- **scikit-learn** fits machine-learning models. Every model is used the same way: create it, `fit` it on
  training data, `predict` on new data.

Python code often reads as `thing.action()`. The dot means "the action that belongs to this thing", so
`x.mean()` is the mean of `x` and `rng.normal(...)` asks the generator `rng` for normal draws. A function
attached to an object like this is called a **method**.

## A bootstrap, line by line {#sec-by-hand}

Bruce & Bruce describe the bootstrap for a sample mean as an algorithm: draw a value from the sample, record
it and put it back; repeat until you have as many values as the sample; record their mean; do all of that
many times; then use the spread of the recorded means as the standard error [@bruce_practical]. Here it is in
numpy, on a six-number sample. Lines starting with `#>` show the output.

```python
import numpy as np
x = np.array([4, 8, 15, 16, 23, 42])
rng = np.random.default_rng(42)
rng.choice(x, size=6, replace=True)
#> array([ 4, 23, 16, 15, 15, 42])
means = np.array([rng.choice(x, size=6, replace=True).mean() for _ in range(1000)])
means.std(ddof=1)
#> 4.902136...
np.percentile(means, [2.5, 97.5])
#> array([ 9.4958, 28.6667])
```

Reading it line by line:

1. `import numpy as np` loads numpy and lets you call it `np` for short.
2. `np.array([...])` turns a Python list into an array: the sample of six numbers, with mean 18.
3. `np.random.default_rng(42)` creates a random-number generator from seed 42. Anyone who runs this gets the
   same draws.
4. `rng.choice(x, size=6, replace=True)` draws six values from `x` **with replacement**, so a value can come
   up twice (15 does here) and another not at all (8). This is one **bootstrap resample**.
5. The next line does that 1,000 times. `for _ in range(1000)` means "repeat 1,000 times" (the `_` is a
   name for a counter you don't use). Each time it takes the `.mean()` of the resample, and `np.array(...)`
   collects the 1,000 means.
6. `means.std(ddof=1)` is their standard deviation, about 4.9: the bootstrap standard error of the mean.
   The textbook formula $s/\sqrt{n}$ gives 5.5. With only six numbers the two are close but not equal; the
   bootstrap needs no formula at all.
7. `np.percentile(means, [2.5, 97.5])` finds the values that cut off the lowest and highest 2.5% of the
   1,000 means. The middle 95% runs from about 9.5 to 28.7: a bootstrap confidence interval.

The `ddof=1` matters. numpy's `.std()` divides by $n$ unless told otherwise, so `x.std()` gives 12.32, while
R's `sd(x)` and `x.std(ddof=1)` divide by $n-1$ and give 13.49. **ddof** stands for "delta degrees of
freedom", the number subtracted from $n$.

::: {.callout-note collapse="true" title="Jargon key — open if a term is unfamiliar"}
- **Package / module** — a bundle of code you load with `import`; `np` and `plt` are the usual short names
  for numpy and matplotlib's plotting module.
- **Array (`ndarray`)** — numpy's block of numbers of one type; one-dimensional like a vector, or
  two-dimensional like a matrix.
- **Shape** — an array's size along each dimension: `(6,)` for six numbers in a row, `(3, 2)` for 3 rows and
  2 columns.
- **Axis** — one of those dimensions; `axis=0` runs down the rows (so `mean(axis=0)` averages each column).
- **Vectorised** — applied to every element at once, in fast compiled code, with no Python loop.
- **Broadcasting** — numpy's rule for combining arrays of different but compatible shapes by stretching the
  smaller one.
- **Method** — a function attached to an object, called with a dot: `x.mean()`.
- **Generator and seed** — the random-number machine (`rng`) and the number that fixes its stream.
- **With replacement** — each drawn value is put back before the next draw, so it can be drawn again.
- **View vs copy** — a view is a window onto an existing array (changing it changes the original); a copy is
  independent.
- **Estimator** — in scikit-learn, a model object with `fit` and `predict` methods.
:::

## numpy: think in arrays {#sec-numpy}

numpy's `ndarray` is Python's answer to R's vector: a homogeneous block of numbers that operations run over *all
at once*, in fast compiled code, with **no Python loop**. It is the same habit as
[thinking in vectors in R](getting-started-in-r.qmd#sec-vectors).

```python
import numpy as np

x = np.array([4, 8, 15, 16, 23, 42])
x * 2                    # array([ 8, 16, 30, 32, 46, 84]) — vectorised
x[x > 15]                # array([16, 23, 42])            — boolean mask
x.mean(), x.std()        # reductions over the whole array (18.0 and 12.32: std divides by n)
M = np.ones((3, 2))      # a 3x2 matrix of ones
M @ M.T                  # matrix multiply (the @ operator)
```

> **In plain words:** `x > 15` makes a list of True/False values, one per element, and `x[...]` keeps the
> True ones. `M.T` is `M` turned on its side (its transpose), and `@` multiplies matrices.

**Broadcasting** is the one idea to internalise: numpy stretches mismatched-but-compatible shapes so
`data - data.mean(axis=0)` centres every column without a loop. It is the source of numpy's speed and,
occasionally, of silent bugs (below).

## Randomness and simulation {#sec-random}

Simulation is numpy's quiet superpower. The modern interface is a **generator** seeded for
[reproducibility](reproducible-quarto.qmd):

```python
rng = np.random.default_rng(42)     # seeded generator
rng.normal(0, 1, size=1000)         # draws from N(0,1)
rng.integers(0, 6, size=10)         # dice
rng.choice(data, size=100, replace=True)   # a bootstrap resample
```

Draw, compute a statistic, repeat — that loop *is* the [bootstrap](../../content/02-inference/the-bootstrap.qmd),
a [permutation test](../../content/02-inference/resampling-and-nonparametric-tests.qmd), and every
[Monte-Carlo](../../content/01-foundations/simulation-and-monte-carlo.qmd) argument in the book. In the
bootstrap the resampling is always with replacement; in a permutation test the data are reshuffled without
it [@bruce_practical]. The figure below is the canonical example.

## Linear algebra, done right {#sec-linalg}

`np.linalg` is where the [matrix formulas](../math/ols-in-matrix-form.qmd) become code — and it is why those
entries **solve** rather than invert:

```python
beta = np.linalg.solve(X.T @ X, X.T @ y)   # normal equations — do this
beta = np.linalg.inv(X.T @ X) @ X.T @ y    # mathematically equal, numerically worse
```

> **In plain words:** both lines compute the least-squares coefficients $\hat\beta = (X^\top X)^{-1}X^\top y$.
> The first asks numpy to solve the equations $X^\top X\,\beta = X^\top y$ directly; the second first builds
> the inverse matrix and then multiplies, which is slower and loses more precision to rounding.

`solve` (and `lstsq`, or a QR/SVD) is faster and more stable than forming an explicit inverse — the practical
lesson from OLS in matrix form, in one line. The [coefficient plot](regressions-in-r.qmd#sec-tidy) in the R
regression appendix computes its estimates exactly this way.

## matplotlib is the figure engine {#sec-mpl}

Every plot in this encyclopedia is matplotlib, written by hand: a `figure`, one or more `axes`, and explicit
marks. No `seaborn`, no `ggplot`-style grammar — just the primitives, so the code says exactly what the picture
means. That is a deliberate house choice, not a limitation.

The pattern under every figure is the same three steps: `fig, ax = plt.subplots()` makes the canvas and a
panel; calls like `ax.plot(...)`, `ax.scatter(...)` and `ax.axhline(...)` add marks; `ax.set_xlabel(...)` and
`ax.set_title(...)` label it. Reading those calls top to bottom tells you everything the figure shows.

## Where scikit-learn fits {#sec-sklearn}

For *applied* machine learning — the [ML track](../../content/ml-track/index.qmd) put to work — **scikit-learn**
gives every model the same three-verb interface, which is most of what makes Python pleasant for ML. The
models themselves (the lasso, trees, boosting) are what Murphy and ISLR explain [@murphy_ml; @islr].

```python
from sklearn.linear_model import Lasso
from sklearn.model_selection import train_test_split

Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0)
model = Lasso(alpha=0.1).fit(Xtr, ytr)     # fit
pred  = model.predict(Xte)                  # predict
model.score(Xte, yte)                       # evaluate
```

> **In plain words:** hold back 30% of the rows as a test set; fit a lasso on the other 70%; predict the
> held-back rows; score how well the predictions match. The test rows play no part in the fit, which is the
> point: ISLR's validation-set approach estimates test error on observations the model never saw [@islr].

`fit` / `predict` / `score` is the same for a random forest, a gradient booster, or a logistic regression — you
swap the estimator and the workflow is unchanged. The concepts behind them live in the ML track; this is the
tooling that runs them.

```{python}
#| label: fig-monte-carlo-pi
#| fig-cap: "Monte-Carlo estimation of π — simulation in one screen of numpy. Left: N random points dropped in the unit square; the fraction landing inside the quarter-circle (orange) is an estimate of its area, π/4, so 4× that fraction estimates π. Right: the running estimate over N draws converges on π (dashed line) at the √N rate the Law of Large Numbers guarantees. No formula for π is used — only random points and counting. This is the whole idea of Monte-Carlo methods, and the reason numpy's vectorised RNG matters."
#| code-fold: true
#| code-summary: "Show the figure code"

import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
N = 4000
pts = rng.random((N, 2))                       # N points in the unit square
inside = (pts[:, 0]**2 + pts[:, 1]**2) <= 1.0  # inside the quarter circle?
pi_running = 4.0 * np.cumsum(inside) / np.arange(1, N + 1)

fig, (axL, axR) = plt.subplots(1, 2, figsize=(8.6, 4.2),
                               gridspec_kw={"width_ratios": [1, 1.15]})

# Left: the drops
axL.scatter(pts[inside, 0], pts[inside, 1], s=5, color="#e8531d", alpha=0.7, label="inside")
axL.scatter(pts[~inside, 0], pts[~inside, 1], s=5, color="#b7b6a8", alpha=0.7, label="outside")
theta = np.linspace(0, np.pi / 2, 100)
axL.plot(np.cos(theta), np.sin(theta), color="#161613", lw=2.0)
axL.set_aspect("equal"); axL.set_xlim(0, 1); axL.set_ylim(0, 1)
axL.set_title(f"{N} random points  →  π ≈ {pi_running[-1]:.3f}", fontsize=10)
axL.legend(fontsize=8, frameon=False, loc="upper right")
axL.grid(False)

# Right: convergence
axR.plot(np.arange(1, N + 1), pi_running, color="#e8531d", lw=1.6)
axR.axhline(np.pi, color="#161613", lw=1.2, ls=(0, (4, 3)))
axR.text(N, np.pi + 0.04, " π", color="#161613", fontsize=10, va="bottom", ha="right")
axR.set_xscale("log")
axR.set_ylim(2.6, 3.7)
axR.set_xlabel("number of draws (log scale)"); axR.set_ylabel("running estimate of π")
axR.set_title("The estimate converges (LLN)", fontsize=10)

fig.suptitle("Monte-Carlo π: random points and counting, nothing else", fontsize=11)
fig.tight_layout()
plt.show()
```

Reading the figure code with the jargon key: `rng.random((N, 2))` is an array of shape `(4000, 2)`, one row
per point; `inside` is a True/False array; `np.cumsum(inside)` is the running count of hits, so dividing by
`1, 2, …, N` gives the running fraction. Everything is vectorised; there is no loop over points.

## Common pitfalls

::: {.callout-warning title="Where the Python stack bites"}

- **Float equality.** `0.1 + 0.2 == 0.3` is `False` (the sum is stored as 0.30000000000000004). Compare with
  `np.isclose(a, b)`, never `==`, for floating-point results.

- **The `std` default.** `x.std()` divides by $n$, not $n-1$: 12.32 rather than R's 13.49 for the six-number
  example. Pass `ddof=1` when you want the sample standard deviation.

- **Broadcasting surprises.** A `(n,)` vector and an `(n,1)` column broadcast to an `(n,n)` matrix — rarely what
  you meant. Check `.shape` when an operation returns something suspiciously large.

- **Views vs copies.** Slicing an array returns a *view*; writing to it mutates the original. Use `.copy()` when
  you need independence, or track down a "why did my data change?" bug.

- **Leakage in scikit-learn.** Fit scalers/imputers on the **training split only**, then apply to test — do it on
  the full data and your [cross-validation](../../content/04-predictive/cross-validation.qmd) score is
  optimistic. Use a `Pipeline` so the preprocessing is refit inside each fold. This is ISLR's rule that test
  observations play no part in fitting [@islr], applied to preprocessing as well as to the model.

- **Reaching for heavy libraries reflexively.** A histogram, a bootstrap, a projection — these are a few lines of
  numpy. Pulling in `seaborn`/`pandas`/`sklearn` for a one-liner adds dependencies and hides the mechanism the
  figure is meant to show.

:::

## From the sources {.unnumbered}

::: {.callout-note collapse="true" title="Who says what"}
- **Bruce & Bruce, *Practical Statistics for Data Scientists*** — the bootstrap as an explicit resampling
  algorithm (draw with replacement, record the statistic, repeat, use the spread), and the
  bootstrap-vs-permutation distinction. The corpus copy is the 2017 first edition, whose code is in R; the
  Python translation here is this encyclopedia's.
- **Reinhart, *Statistics Done Wrong*** — estimating power by simulating many artificial datasets.
- **Murphy, *Machine Learning: A Probabilistic Perspective***, and **James et al., *ISLR*** — the models behind
  scikit-learn's estimators and the train/test discipline (the validation-set approach).
- **What the corpus does not cover:** none of the source texts teaches numpy, matplotlib or scikit-learn as
  software. Function names and behaviour on this page (`default_rng`, `ddof`, broadcasting, views,
  `fit`/`predict`/`score`) are standard library behaviour, checked by running the code, and are not
  attributed to any source. An earlier version of this page credited the numpy idiom to Bruce & Bruce and
  the leakage caution to ISLR; both credits were broader than the texts support.
- **This repository** — every figure is hand-built numpy + matplotlib; the Monte-Carlo π above is the template
  for "simulate, then plot."
